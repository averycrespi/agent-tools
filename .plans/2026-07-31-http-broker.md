# http-broker Plan

## Goal

Add `http-broker`, a host-native MITM HTTP/HTTPS forward proxy for sandboxed AI agents. It decides per connection whether to intercept, tunnel, or deny; injects credentials the sandbox never holds; and records every request to a SQLite audit log surfaced through a read-only dashboard. It is the network-layer sibling to `mcp-broker`: the same "the agent does not hold the credential" premise, applied to raw HTTP instead of MCP tool calls.

**Scope of the guarantee, stated up front.** Enforcement is _cooperative_: it rests on the sandbox honoring `HTTP_PROXY`/`HTTPS_PROXY`. An agent that unsets those, uses `curl --noproxy`, or opens a raw socket bypasses this tool entirely. This matches `sandbox-manager/DESIGN.md:15`, which states the sandbox "is not a data-loss-prevention boundary" and that guest egress is intentionally allowed. http-broker makes credential handling safe for cooperating traffic and makes that traffic auditable; it is not a containment boundary. Network-level enforcement (guest firewall rules permitting egress only to the proxy) is the honest v2 direction and must be named as such in `DESIGN.md`.

## Acceptance Criteria

- **AC-1:** `http-broker serve` binds a proxy listener and a dashboard listener, both loopback. A non-loopback `listen` address is rejected at startup with a named error.
- **AC-2:** A request matching an `intercept` rule reaches upstream carrying the injected headers; the client's own request contained none of them, and the client receives the upstream response unmodified. One rule may inject several headers.
- **AC-3:** With `fallthrough: "deny"`, a request to an unmatched host receives 403 with `X-Http-Broker-Reason`, audited `outcome=blocked`.
- **AC-4:** With `fallthrough: "tunnel"`, a request to an unmatched host is relayed, audited `interception=tunnel` with host, port, bytes and duration, and NULL `method`/`path`.
- **AC-5:** A `mode: "tunnel"` rule keeps its host un-intercepted even when `fallthrough` is `deny`; a host-only `mode: "deny"` rule rejects at CONNECT before any upstream dial; a host reached only via a path-scoped `deny` rule forwards non-matching paths with no injection, audited `mode=implicit-allow`; and when a request matches both an `intercept` and a `deny` rule, **deny wins regardless of rule order**.
- **AC-6:** Rules and credentials loading rejects, with an actionable message: a rule missing `host`; a `mode: "tunnel"` rule carrying `path` or `method`; duplicate rule names; an unknown `mode`; a bad glob; two host-only rules of differing mode matching the same host; and any host glob that reduces to an ICANN public suffix after stripping leading wildcards. Per-rule errors name the rule; a file-level JSON parse error names the file and byte offset.
- **AC-7:** `SIGHUP` reloads `rules.json` without restart. An invalid file leaves the previous ruleset serving traffic and logs an error.
- **AC-8:** A referenced credential that cannot be resolved produces 403 and an audit row tagged `credential_unresolved`. A resolved credential's value never appears in logs, audit rows, any dashboard response, or `credential list` output.
- **AC-9:** Every credential — whichever source it comes from — carries bound host globs, and injection into a request whose canonical host falls outside them yields 403 with reason `credential-host-scope`, an audit row tagged `credential_host_scope_violation`, and no bytes on the wire. For a rule injecting several credentials, **all** are resolved and host-checked before **any** header is mutated, so a partially-injected request can never be dispatched. Rules loading warns when a rule's host glob is not obviously covered by a referenced credential's bound list.
- **AC-10:** Every request writes exactly one audit row carrying host, port, and outcome. No row contains a request body, a response body, or a header value. Query strings are stored with credential-shaped parameters redacted, case-insensitively, including the AWS SigV4 presigned-URL parameter names.
- **AC-11:** Upstream dials are guarded on **both** the tunnel and MITM paths against IMDS, loopback, private, link-local, multicast and unspecified addresses; against alternate IP-literal encodings (hex, decimal, IPv6-mapped IPv4); against IPv6 ULA and link-local; and against DNS rebinding, by validating every resolved address and dialing the validated address rather than the hostname.
- **AC-12:** No dashboard endpoint mutates config, rules, or credentials — demonstrated by state snapshots before and after driving every route listed in `docs/dashboard.md`, including with adversarial query parameters. Every endpoint requires the bearer token except `GET /ca.pem` and `GET /healthz`.
- **AC-13:** A streaming upstream response reaches the client incrementally rather than buffered to completion.
- **AC-14:** A plain-HTTP absolute-form request (`GET http://host/path`) is evaluated by the same rules pipeline, with the same modes and injection.
- **AC-15:** `examples/provision/configure-http-broker.sh` is idempotent; sets `HTTP_PROXY`, `HTTPS_PROXY`, and all six CA variables named in Constraints; sets `NO_PROXY` including `host.lima.internal`, `localhost` and `127.0.0.1` so `mcp-broker` and `local-gomod-proxy` stay reachable; and installs the CA — shipped in by `sandbox-manager` `copy_paths`, not fetched — to `/usr/local/share/ca-certificates/http-broker.crt` followed by `update-ca-certificates`.
- **AC-16:** Host-glob matching always compares the normalized, port-stripped host, so a rule naming a bare host matches a CONNECT on any port. Tunnel decisions — **including the `fallthrough` path** — are restricted to port 443 unless a rule opts in via an explicit `ports` list.
- **AC-17:** All ten steps of the root `CLAUDE.md` "Changing the Go Tool Set" checklist are complete, and `make audit` passes from the repo root.
- **AC-18:** `docs/security-model.md` exists with sections for trust boundaries, a numbered list of guarantees, an explicit out-of-scope list, and a compromise-response procedure covering a leaked bearer token, a leaked `ca.key`, an exposed `audit.db`, and a leaked credential.
- **AC-19:** An unauthenticated `GET /healthz` on the dashboard listener returns `ok` and is documented, together with the wedged-but-listening failure mode and how to detect it externally.

## Non-Goals / Out of Scope

- **Human-in-the-loop approval.** It belongs where the arguments are visible, which is `mcp-broker`.
- **Learned rules or dashboard-driven policy writing.** The dashboard is read-only.
- **Encrypted secret store.** No SQLite secrets table, no crypto of our own, no DEK/KEK, no master-key rotation. The OS keychain holds values directly. Distinct from host binding, which AC-9 does require.
- **Per-agent identity.** One shared bearer token. Grants deferred to v1.1 on `mcp-broker`'s TTL overlay model.
- **Header-regex and request-body matchers**, and therefore request-body buffering in any form.
- **Injection into path, query, or body.** Headers only.
- **WebSocket and other `Upgrade` traffic through MITM.** `Upgrade` is stripped as hop-by-hop, so a WS handshake through an `intercept` rule fails. Route such hosts with `mode: "tunnel"`; document the failure signature.
- **Response rewriting**, redirect following, rate limiting, non-HTTP protocols.
- **Network-level egress enforcement.** Named in the Goal as the v2 direction.
- **Changes to `sandbox-manager`**, beyond documenting the `copy_paths` entry AC-15 requires the user to add.

## Chosen Approach

A single Go binary with two loopback listeners. `:8220` accepts HTTP `CONNECT` and absolute-form plain HTTP; `:8221` serves the read-only dashboard, the SSE feed, unauthenticated `GET /ca.pem`, and unauthenticated `GET /healthz`.

**Two ports, not one.** `mcp-broker` shares a port because MCP and its dashboard are both ordinary HTTP. A forward proxy is not, and sharing would make the dashboard reachable _through_ the proxy.

**Three modes, one rules list.** Each rule matches a mandatory `host` glob plus optional `path`, `method`, and `ports`, and carries `mode: intercept | tunnel | deny`. `intercept` rules may carry `inject`. `tunnel` as a mode subsumes the reference branch's separate `no_intercept_hosts` list.

```json
{
  "fallthrough": "tunnel",
  "rules": [
    {
      "name": "github-issues",
      "host": "api.github.com",
      "path": "/repos/*/*/issues",
      "method": "POST",
      "mode": "intercept",
      "inject": {
        "set": {
          "Authorization": "Bearer ${cred.gh_bot}",
          "X-GitHub-Api-Version": "2022-11-28"
        },
        "remove": ["X-Agent-Hint"]
      }
    },
    { "name": "pinned-sdk", "host": "*.pinned-sdk.com", "mode": "tunnel" },
    { "name": "no-ads", "host": "*.doubleclick.net", "mode": "deny" }
  ]
}
```

`inject.set` is a map, so one rule may inject several headers. `name` is required and unique — audit rows and the dashboard attribute by name.

**One credential reference form, two sources.** Rules always write `${cred.<name>}`. A credential record is `{value, hosts}` and comes from either the OS keychain (`credential set <name> --host ... --host ...`, value from stdin, stored as a JSON envelope under service `http-broker`) or an `env_credentials` block in `config.json` mapping a name to `{var, hosts}`. **Both sources carry bound hosts and go through the identical host check.** An earlier draft had rules reference `${keychain.*}` and `${env.*}` separately, which silently exempted env-sourced credentials from host binding — the single enforcement path exists to make that class of gap impossible rather than documented.

The keychain resolves the launchd problem: launchd does not source shell profiles, so an env-only design forces every API key into `~/Library/LaunchAgents/*.plist` in plaintext. With the keychain the plist carries `PATH` and nothing else. A `gui/$UID` agent runs in the logged-in session, so the login keychain is unlocked; credentials resolve lazily at request time behind a short TTL cache, so an unavailable keychain fails individual requests with a clear audited error rather than blocking startup. `env_credentials` exists so the e2e suite never touches a developer's real keychain and shell-run development stays easy; `serve` logs a prominent startup warning naming every credential sourced that way.

**Host binding is a second, independent check.** The rule's `host` glob decides _whether a rule fires_; the credential's bound globs decide _whether this credential may go to this host_. Both must pass. Without the second check a single rule-authoring slip sends a real token wherever the rule now matches.

**The CONNECT-time decision is host-keyed**, because at CONNECT only host and port are visible. The target is split with `net.SplitHostPort` and the host normalized _before_ any glob comparison; rules never match a `host:port` string (AC-16). Evaluation:

1. Collect rules whose `host` glob matches the normalized host and whose `ports` admit the target port. For `tunnel` and `deny` rules `ports` defaults to `[443]`; for `intercept` it defaults to any port.
2. If any match has `mode: intercept` → **MITM**, since the path is needed to know which applies.
3. Else if a host-only `tunnel` or `deny` rule matches → apply it at CONNECT. Two host-only rules of differing mode matching the same host is a load-time error (AC-6), so this is never ambiguous.
4. Else — only path-scoped `deny` rules match — → **MITM** and evaluate per request. A request matching a deny rule gets 403. **A request matching no rule is forwarded with no injection, audited `mode=implicit-allow`**; the host is already known to policy, so `fallthrough` does not apply.
5. No host match → `fallthrough`, itself subject to the port-443 default.

`mode: "tunnel"` rules must be host-only (D5): tunneling is decided before any request exists. A path-scoped `deny` is coherent, since interception can precede rejection. At the per-request stage, **deny beats intercept regardless of order** (D18) — otherwise rule ordering silently decides whether a credential reaches a path the operator believed was denied.

**Everything else follows `mcp-broker`:** JSON config split across `config.json` and `rules.json` with `Refresh` backfill; a shared bearer token with `token rotate`; foreground `serve` with no pidfile, supervised by launchd, reloaded with `launchctl kill HUP`; embedded dashboard assets with a drop-on-full SSE feed. Dashboard assets stay split across three files rather than collapsing into one.

## Design Decisions

- **D1: Selective reuse.** Port `ca`, `netguard`, `hostnorm`, `hostmatch` with attribution; write everything else fresh. Those four have no coupling to dropped features and carry the edge-case coverage most expensive to re-derive.
- **D2: Keychain as the default credential source.** Resolves the launchd tension without a plaintext secret file, at the cost of a `go-keyring` dependency and a small CLI group — far less than the encrypted-store subsystem it replaces.
- **D3: No credential chunking.** API keys plus a short host list stay under the macOS ~4096-byte limit. `credential set` fails clearly if exceeded.
- **D4: Keychain unavailable is a hard error, never a silent file fallback.** The reference falls back to a `0600` file, producing the plaintext-on-disk outcome this design rejects.
- **D5: `mode: "tunnel"` rules must be host-only.**
- **D6: Rule names required and unique.**
- **D7: Unresolvable credential fails closed with 403.** Forwarding with the placeholder intact is indistinguishable in the audit log from "no rule matched", hiding a real misconfiguration.
- **D8: netguard wraps both dial paths.** The reference guards only the MITM transport while `serveTunnel` calls bare `net.Dial` (`internal/proxy/connect.go:237`) and IP literals always route to tunnel, so an agent reaches `169.254.169.254` through it. The port must fix this and prove it on the tunnel path.
- **D9: No request-body buffering anywhere.**
- **D10: CONNECT target wins over the in-tunnel `Host` header.**
- **D11: Leaves bind to the CONNECT hostname, not the TLS SNI.** Issuance branches on `net.ParseIP` to populate `IPAddresses` rather than `DNSNames` for IP-literal targets, or MITM of an allowed IP literal fails opaquely.
- **D12: Strict TLS upstream.** System trust store, verification on, `MinVersion: tls.VersionTLS13`.
- **D13: Leaf cache is LRU-bounded** and retains the reference's clock-skew buffer, which re-issues within 5 minutes of a validity boundary so skewed clients fail clearly rather than opaquely.
- **D14: Query redaction is case-insensitive and covers presigned URLs.** Redact `key`, `token`, `signature`, `sig`, `auth`, `api_key`, `access_token`, `password`, `X-Amz-Signature`, `X-Amz-Credential`, `X-Amz-Security-Token`, `X-Goog-Signature`. Agents legitimately send presigned URLs, and the audit DB plus dashboard would otherwise become the leak channel AC-10 closes.
- **D15: Recovery is a rules edit, not a process kill.** With proxy variables baked into the guest shell, killing `serve` points the sandbox at a dead socket and causes total network loss — worse than the misbehavior prompting the kill. The kill switch is an all-tunnel `rules.json` plus `SIGHUP`.
- **D16: One glob implementation.** `internal/rules` and the credential host check both call `hostnorm.MatchHostGlob`/`NormalizeGlob` rather than compiling their own regex. The reference shipped three copies and documented the drift risk in a code comment; divergence between rule matching and credential-scope matching would be a silent containment inconsistency.
- **D17: Injection is atomic.** All `inject.set` templates for a rule are expanded and host-checked before any header is written to the upstream request; a single failure discards the whole in-progress request. Copied from `internal/inject/injector.go:85-91`, which exists precisely so a partially-injected request cannot reach `RoundTrip`.
- **D18: Deny beats intercept** at the per-request stage, regardless of rule order.
- **D19: A liveness endpoint is required.** `mcp-broker` ships `/healthz` for this reason, and the failure mode is worse here: launchd `KeepAlive` restarts a _crashed_ process, but a wedged-but-listening proxy causes total sandbox network loss and answers no signals, so the D15 runbook cannot help.

## Risks

- **The boundary is cooperative and may never be tightened.** The likeliest failure is not a breach but quiet uselessness: the tool stays on `fallthrough: tunnel` forever, producing an audit log that looks complete while missing anything uncooperative — worse than no log, because it creates false confidence. Mitigation: the Goal and `DESIGN.md` state the limit plainly; the README documents tightening as the intended end state.
- **A predecessor with 192 commits was abandoned for reasons nobody wrote down.** If it was maintenance burden or complexity, that applies here too. Mitigation: T-1 must establish and record the reason before the build proceeds.
- **Keychain access under launchd** may prompt on first read, and an unattended prompt looks like a hang. Mitigation: lazy per-request resolution behind a TTL cache; log failures with remediation; document granting always-allow on first use.
- **Headless Linux has no Secret Service daemon**, so `go-keyring` fails and D4 makes that fatal. The intended host is macOS; CI and Linux development use `env_credentials`, which still carry host binding. Documented in the README.
- **`fallthrough: "deny"` breaks a fresh sandbox** until rules exist. Mitigation: ship `tunnel` as the generated default with a commented starter allowlist.
- **Clients that ignore proxy variables escape entirely.** Documented limitation of the cooperative model.
- **The real MCP client is not Go.** V-19 proves the `NO_PROXY` carve-out under Go semantics only; Node's undici honours proxy variables inconsistently. Mitigation: a documented manual check against the real agent wiring after first provisioning.
- **Cert-pinning clients** fail against our leaf. Mitigation: a `mode: "tunnel"` rule, documented with the error signature.
- **CA rotation invalidates every provisioned sandbox** with no overlap window. Mitigation: documented runbook — rotate, then re-run provisioning everywhere.
- **A wedged-but-listening proxy causes total sandbox network loss**, and launchd `KeepAlive` only catches crashes. Mitigation: `/healthz` (D19) plus a documented external probe; the D15 rules-edit kill switch does not help against a process that answers no signals.
- **Killing the process is worse than the misbehavior**, because proxy variables are baked into the guest shell. Mitigation: D15's runbook, in the README operations section.
- **Ongoing CVE exposure.** A hand-rolled HTTP/2 MITM terminator needs tracking — the reference required explicit Rapid Reset and CONTINUATION-flood hardening. Accepted standing cost, named in `DESIGN.md`.

## Deferred Findings

### Residual after the review fix wave (sha: 26f4ea4)

The scoped re-review of the fix wave raised four findings. None is Critical; per `review-changes`, one wave and one re-review then stop, so these are recorded rather than fixed. **The first two should be handled before this merges.**

- **Important — the SSE half of the no-leak sweep does not actually test anything, and the wave's commit message overstates it.** `TestNoLeak` (`test/e2e/audit_test.go`, `readSSE`) subscribes to `/api/events` _after_ the credential-injecting request has already fired and its audit row has already been awaited, so the subscription only sees future records. The event it manufactures to populate the stream is a `GET /healthz`, which writes no audit row at all — so `readSSE` returns `""` every run and the sentinel checks pass on an empty string. The SSE sink is therefore **not** swept, despite commit `26f4ea4` claiming all four sinks are. The audit-DB, process-log and CLI sinks _are_ genuinely covered. Fix: after subscribing, re-issue the actual credential-injecting request through the proxy so a real record flows through `Subscribe`, instead of nudging with `/healthz`.
- **Important — `hijacked.Add(1)` runs after `hijack(w)` returns, which is the same event that lets `Shutdown` proceed.** `internal/proxy/mitm.go` and `internal/proxy/proxy.go` both increment the WaitGroup after the connection has already left `http.Server`'s tracked set, so there is a window where `WaitForRelays` observes a zero counter and returns before the handler's `Add`. This violates `sync.WaitGroup`'s requirement that an `Add` from zero happen-before a concurrent `Wait`. The drain fix therefore narrows the window rather than closing it. Fix: `Add(1)` before calling `hijack(w)`, with `Done` still deferred and guarded against the hijack-failed path.
- **Minor — `rules.NormalizePath` does not collapse dot segments on non-rooted input.** `path.Clean` runs before the leading `/` is prepended, so `NormalizePath("../admin/secret")` returns `/../admin/secret`. Not reachable today: the only call site is fed `r.URL.Path`, which per the HTTP request-target grammar is either empty or already rooted. But the function is exported and documented as general-purpose, so a future caller could reopen the traversal gap silently. Fix: prepend `/` before calling `path.Clean`.
- **Minor — the dashboard's per-request keychain read has no timeout.** `credentialLister` calls `Keychain.Describe` per referenced credential on every `/api/credentials` request, with no context. A stalled keychain prompt or locked session blocks that request's goroutine indefinitely. Bounded in blast radius to the requesting goroutine. Fix: thread a short context into the dashboard's keychain lookup, distinct from the CLI path where an unbounded wait is acceptable.

### Earlier

- **T-8 — a test-only seam was added to `netguard`, and the user should review it.** Every mock upstream a test can start listens on loopback, which the address guard refuses by design, so without a seam no e2e test could exercise _any_ allowed path — not a tunnel, not interception, not injection. `Dialer.SetExemptions` takes exact `host:port` strings only (no globs, no ranges, no address classes), is reachable only through the `HTTP_BROKER_TEST_ALLOW_ADDRS` environment variable rather than any config field, and `serve` logs a warning naming every exemption at startup. Refusal tests deliberately leave it unset so the guard stays under test. The plan did not anticipate this tension between AC-11 (block all local addresses) and the e2e halves of AC-2/AC-13/AC-15 (reach a local mock upstream); this is the narrowest resolution I could find, but it is a security-relevant addition and worth a second opinion.
- **Host-only rule overlap is detected at decision time, not load time.** Two host-only rules of differing mode whose globs overlap without being written identically (`api.example.com` and `*.example.com`) still load. `ConnectDecision` now prefers deny so the outcome cannot depend on file order, but the operator gets no load-time warning. Full glob-overlap detection between arbitrary wildcard patterns is a materially harder problem and would need its own design decision.

Not this change's to fix.
