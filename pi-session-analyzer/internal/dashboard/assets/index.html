01 / TIME RANGE

Operational overview

?

Totals and charts for sessions whose start time falls in the selected range, bucketed by calendar unit in the selected timezone. Token categories are always reported separately; provider input is never folded into generated work. Untimed sessions are counted but excluded from time charts.

Sessions started

?

Each bar is one calendar bucket. The outlined bar is the current, still-partial bucket. Select a bar to narrow the session matrix below; the collapsible table in this panel lists the same values as text.

Per-bucket trends

?

Small multiples of per-bucket totals: spend, tokens, compactions, broker guards, detector findings by severity and classification, goal outcomes, and final stop reasons. Series that are zero across the whole range are listed instead of drawn.

Classifiable tool outcomes

?

A tool call is classifiable when a result carries an explicit error flag, or an MCP failure is recognizable in unflagged output (inferred). Error rate divides confirmed plus inferred errors by classifiable calls only; unknown calls never count toward rates.

Detector freshness

?

Fresh findings from the latest detector run over each session in range: counts by severity (error / warn / info), by classification (structural evidence vs heuristic pattern), and run coverage (sessions where the detector succeeded, failed, or has not run).

Goal and stop mix

?

Final goal state recorded by each session (complete, active, or absent when no goal was set) and the stop reason on each session's last assistant message.

Session shape

?

How sessions in range are distributed by total stored records and by message turns.

Skill usage

?

A skill invocation is a read tool call whose target is a skill's SKILL.md instruction file; the skill name is the file's parent directory. Counts cover sessions started in the selected range. Skills that exist but were never read do not appear.

03 / LINEAR EVIDENCE

Session drilldown

?

Source-ordered evidence for one session. Stored text stays collapsed until you open it; opening requests bounded detail from the local index.

Per-tool outcomes

?

Outcome classification for this session's tool calls, using the same confirmed / inferred / unknown rules as the overview.

Detector status and findings

?

Latest run status per detector, current findings with line-anchored evidence, and stale evidence retained from earlier runs — kept separate because it no longer reflects the current session.

Split-token sequence and compactions

?

One bar per message in source order. Width compares each message's total usage to the session's largest message; segments split that total by category. Compaction markers show the tokens held before the compaction ran.

Bar width is the message total relative to the largest message. Provider input Output Reasoning Cache read Cache write

Goal progression

?

Goal-state snapshots in source order, ending at the final recorded state.

TODO progression and final list

?

TODO snapshots with item counts by status, followed by the items on the final list. Invalid snapshots are reported with their parse error instead of counts.

Source-ordered session stream

?

Every stored record in source-line order: messages, tool calls and results, events, and custom state. Open an entry to fetch its bounded content from the local index.

Stored text remains collapsed until explicitly opened.
