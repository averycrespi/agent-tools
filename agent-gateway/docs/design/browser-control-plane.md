## Git administration and traffic

The dedicated Git group contains Routing, Credentials, Repositories, Grants and Traffic at
`#/git/routing`, `#/git/credentials`, `#/git/repositories`, `#/git/grants` and `#/git/traffic`.
Routing is a singleton page showing the read-only enforcement state, revision and
complete enabled-origin list. Add/remove HTTPS origin rows and confirm the full
current/proposed replacement under an exact profile ETag. An empty list is valid;
removing an origin returns it to HTTP policy. No repository grants or client proxy
settings are created. Failed reads retain explicitly stale facts and block saves;
conflicts preserve drafts for deliberate revision review, and uncertain saves
remain blocked without replay. Controls are frozen during submission.
Configuration supports `new` and ID detail; traffic supports read-only ID detail.
All compose existing session/view, collection, mutation, confirmation, dirty-form,
write-only sink and table primitives. No HTTP or MCP authority is shared.
Repository destination is immutable; explicit aliases cannot retarget it. Grant
push rules include read, with separately selected create/update/delete operations
and exact/prefix selectors. Expired grants and unavailable credentials are explicit.
Credential values never enter drafts, confirmation, storage or read APIs. Exact
ETag conflicts retain drafts for deliberate revision review; uncertain mutations
remain blocked without replay. Git mutation form controls are disabled while a
request is in flight, so acknowledgement cannot discard newer, unsubmitted edits.
Drafts remain dirty until acknowledgement; rejection preserves navigation protection.
Resource identity and primary status stay outside the single neutral detail task.
Git metadata and confirmation facts use shared aligned rows; admission-time
references remain an unboxed disclosure inside the recorded-exchange task.
Grant creation selects existing named agents and repositories; edit keeps these
relationships immutable and named. Repository creation selects a compatible,
available Git credential for its HTTPS origin or explicitly None for a public
repository. Duplicate names include stable IDs; selected relationships retain a
secondary ID beside the control so a narrow native selector cannot hide their
identity. Bounded snapshot traversals cover all choices, not just page one; loading and failure preserve drafts, and a missing
or incompatible selected credential never silently becomes None. Relationship
names also appear in lists, details and confirmation. Alias and push-rule editors
share grouped add/remove rows and form-action spacing.

Git resource tables explicitly request name ascending (repositories/credentials)
or description ascending (grants), with **Unnamed Git grant** fallback and
ID-ascending ties. Full-inventory filters follow the columns: repository name/ID,
canonical destination and credential name/ID; credential name/ID, origin and
availability; grant description/ID, repository name/ID, agent name/ID and state.
Names use typo-tolerant recognition, IDs literal case-sensitive substrings, and
canonical destinations/origins literal case-insensitive substrings. All visible
columns sort through the backend; Reset clears filters, not ordering. Applied
queries survive detail/back navigation; create locations remain queryless.

Repository views share one authorized routing-profile read, never one per row.
An active profile missing the exact normalized canonical HTTPS origin shows
**Not routed** beside the destination and in detail/create review, with a contextual
**Git routing** link. Explicit same-origin `.git` aliases have the same coverage;
no alias is added automatically. Loading, unavailable/stale profile and inactive
routing are distinct from uncovered. Origin coverage says nothing about grants,
material readiness or successful access. It does not block saving. Invalid draft
coordinates have unknown coverage rather than an inferred match.

Traffic uses bounded newest-first server-selected pages with shared Previous/Next
controls and manual/coalesced refresh, not an independent polling or stream owner.
It shows admission separately from transport and upstream report. Historical
configured labels, references and counts are not current authority. Missing
completion/report is unknown; discovery and probes are not pushes. Reported
success/failure/partial success is not independent verification of remote effects.
Incomplete/unknown pushes require remote reconciliation, not a retry shortcut.
No observed refs/OIDs, arbitrary upstream messages or secrets enter the browser.

## HTTP credential administration

HTTP > Credentials is a distinct navigation group and operator surface at `#/http/credentials`, with `new` and credential-ID suffixes. It uses the shared session, collection, invalidation, mutation, dirty-form and write-only-sink owners. List/detail show identity, HTTPS boundary, safe header recipe, material availability and referencing grant IDs; no stored-secret reveal exists. The resource table defaults to Name ascending across the authoritative collection, with ID-ascending ties, and has ordered Name or ID, HTTPS boundary, Header recipe and Status filters. All four columns support server-backed sorting. Reset clears only filters, preserving sorting. Safe name/boundary host and port/header and fixed-prefix metadata use authoritative pre-pagination recognition; IDs use literal case-sensitive substring matching. Configured/Unavailable select material evidence, not later keyring access. Recognition never searches material or changes wildcard boundary authority; referencing grants remain links, not a second table. Create/edit review the proposed scope and recipe; the service canonicalizes and validates them. Rotate/delete require consequence confirmation. Secret fields clear on submission, cancellation, navigation and session loss. Errors remain local; known client validation failures identify the field and failed predicate, including secret clearing. Ordinary read errors request a fresh read without implying an uncertain mutation. A failed refresh retains matching detail and safe metadata drafts but blocks writes, including the final handoff from an already-open confirmation; rejected handoffs clear write-only material. A revision conflict clears write-only material, preserves safe edits, and requires the operator to explicitly adopt the refreshed, reviewed revision before reconfirming; refresh never silently rebases or resubmits the draft. Submitting and uncertain operations freeze editable fields. Uncertain outcomes block replay and require inspection. A referenced credential cannot be deleted. Grant references link to the HTTP grant detail. Traffic history is a separate read-only surface, not a proxy listener.

## HTTP grant administration

HTTP > Grants (`#/http/grants`) uses the shared authoritative table filters/sorts, snapshot pagination, session/view refresh and mutation owners. `new`, grant-ID and `test-access` suffixes are closed locations. Agent detail exposes HTTP default in the consolidated Edit agent card. One Save agent PATCH contains only dirty identity/state/visibility/default fields and uses the unified principal ETag. State or default changes require one combined confirmation of all proposed changes; cancel sends no mutation. Conflicts preserve drafts and require deliberate review of refreshed values/revision. Unknown outcomes cannot be replayed; navigation remains guarded while a draft is dirty. The grant table orders Grant, Agent, Destination, Type, Status and Expires and reflows through the shared narrow-table primitive. Destination host is the host-only recognition filter. Active is current/green and Expired neutral. All accepted sort/direction pairs and exact `principal_id` constraints round-trip; the latter appears as a separate removable exact-agent chip, qualifies matching counts and participates in Reset.

HTTP grant detail separates saved facts from its always-visible editor: the description (or **Unnamed HTTP grant**) heads the page, with the complete selectable ID secondary. **Grant details** uses one neutral outer task surface with plain headed groups and aligned label/value rows for the named agent and identity, policy, credential identity/material availability, expiry and creation time. Inapplicable fields, absent credentials and unavailable relationships remain distinct. Credential material is **Unknown** when its record cannot be read or found; **Unavailable** requires an authoritative record reporting missing material. The existing bounded agent/credential choices serve both details and editing, without per-record lookups.

**Edit grant** is an always-visible sibling task initialized with current values. Cancel resets the draft and returns focus to the resource heading; a dirty draft requires deliberate discard. Saved facts stay visible and separate from the draft. Confirmation shows complete current and proposed values. Revision conflicts retain the draft and require explicit refreshed-value review before reconfirmation. Pending and uncertain changes cannot be collapsed to reset mutation evidence. Read failure retains the matching details and editor, marks facts stale and blocks writes. Only acknowledged saves reset the editor to saved values, focus the resource heading and announce **Grant saved** through the shared route-surviving toast. The acknowledged response supplies authoritative saved facts immediately; a failed subsequent refresh reports **Grant saved; refresh unavailable** independently and permits only a fresh read, not another write against unverified data. Rejection and uncertainty remain local, never success. Delete retains its own destructive confirmation and the shared action-row sizing, separate from edit submission.

One adaptive form edits all four explicit types: principal, description, destination and expiry are common; request types add scheme, method rows and path match; allow types expose local/private consequences; only request allows offer whole-scope-compatible HTTPS credentials. Tunnel selection prominently warns of opaque request-policy and injection bypass. No wizard, HTTP self-service request, traffic shortcut or agent-first MCP redesign exists. Drafts/previews are bounded, session-local and never browser-persisted. Current policy and confirmation expose credential identity and local/private permission alongside destination, method and path; confirmation also identifies the selected agent and expiry. Refreshed current facts remain visible while a retained draft adopts a new revision. Exact ETag conflicts require fresh inspection and explicit reconfirmation; uncertain changes have no replay path.

Test access selects principal and request URL/method or explicit CONNECT host/port. Method is a native dropdown, initially GET, with common methods and a Custom uppercase token input for supported extension methods; CONNECT stays in its separate destination mode. It calls the actual policy evaluator once, and displays deciding default/grants, transport, credential conflicts and local-access requirements. Network/TLS/material are explicitly unverified; the response confers no future admission authority. Preview targets never enter browser locations, audit, events or logs.

## Browser development boundary

The frontend development path is build/test-only and uses a second independently managed numeric-loopback Vite process. It serves authored source and local HMR, admits only segment-bounded `/api/v2/` traffic to one fixed numeric-loopback Gateway origin, rewrites only the exact frontend Origin, and preserves the host-only cookie/CSRF boundary without adding production CORS or alternate-Origin authority. It never supervises Gateway, proxies `/mcp` or `/oauth/callback`, writes the embedded asset directory, or enters the production import graph; OAuth callback authority remains at Gateway. The operational contract is documented in [frontend development](../maintainers/frontend-development.md).

## Browser state and workflow ownership

### Production assets and navigation

The developer control application is built from strict TypeScript and Preact with Vite into a fixed embedded HTML, stylesheet, and module allowlist. The checked-in bundle contains no external or inline active content, source maps, chunks, or runtime Node dependency and uses the fixed restrictive CSP.

The application is branded **Agent Gateway**. Primary navigation separates shared administration from the MCP domain: **Overview**, **Agents**, **Audit Log**, **System** in one unlabeled group; then **HTTP** (Credentials, Grants, Traffic), **Git** (Routing, Credentials, Repositories, Grants, Traffic) and **MCP** (Servers, Tools, Grants, Requests, Invocations). Groups are not new destinations or domain editors. MCP collection page titles include their protocol: **MCP Servers**, **MCP Tools**, **MCP Grants**, **MCP Access Requests**, and **MCP Invocations**. Creation titles are **Create MCP Server** and **Create MCP Grant**. Sidebar and tab labels remain short; **Audit Log** matches its navigation label. Invocations needs no explanatory subtitle and presents only existing MCP invocation evidence, separately from Audit Log; no additional protocol coverage or placeholder is implied. These are history destinations, not identity directories. Audit Log retains all existing audit attribution, including system and offline maintenance events; its label is not an actor filter. Overview remains shared, with protocol-specific summaries labeled MCP. System optional history reports the shared MCP/HTTP/Git budget, delivery, fault and pruning boundary. Separately labeled process observations are not history/query totals. Desktop and narrow disclosure navigation share the same ordered links, current-destination semantics, keyboard handling, and state owners.

One closed domain-grouped hash grammar owns browser locations: `#/mcp/servers`, `#/mcp/tools`, `#/agents`, `#/mcp/grants`, `#/mcp/access-requests`, `#/mcp/invocations`, `#/audit-log`, `#/http/credentials`, `#/http/grants`, `#/http/traffic`, `#/git/routing`, `#/git/repositories`, `#/git/grants`, `#/git/credentials`, `#/git/traffic`, and `#/system`. Detail and create suffixes remain beneath their owning collection; server-owned `operations/{id}`, `auth-flows/{id}`, and `descriptors/{id}` remain beneath `#/mcp/servers/{id}`. System create destinations remain unchanged. Retired `#/access/principals`, `#/activity/audit`, `#/access/grants`, `#/access/requests`, `#/activity/invocations`, and other undeclared paths are invalid, with no aliases or redirects. Valid former `#/principals` collection, detail and create links are canonically replaced with `#/agents`, retaining declared filter/sort state within the fragment and the outer URL query. Invalid suffixes or queries still fail closed; unrelated retired paths gain no redirect. Agent detail/create and audit detail suffixes follow their canonical collection; this browser location cleanup changes no API endpoints. Create and edit expose HTTP default as parallel **Block requests** / **Allow requests** choices; create initially selects Block requests and submits the selected value in its single atomic creation. Review and Agent details use the same labels, with details reflecting persisted settings. Default allow supplies no credential, tunnel permission or local/private access and does not override explicit policies. Invalid locations retain the safe fixed fallback and navigation notice, never a resource lookup or mutation inferred from the rejected path. No pathname fallback serving is introduced. Location naming does not change the shared theme owner, session epochs, refresh/pagination, mutation coordination, or one-time-secret sinks.

Its manual fragment parser accepts only ASCII `#/` locations up to 2,048 bytes from the closed destination table, canonical Gateway IDs, and destination-specific filters. It rejects path percent escapes, controls, empty/trailing segments, duplicate or unknown keys, cursors, unapproved text, and unknown enumerated values before API work or rendering. Recognition filter text is percent-encoded, bounded to 256 UTF-8 bytes per value, and excludes control/format characters. Server inventory and tool/catalog filters apply these bounds to both the supplied and NFKC/lowercase forms before navigation. Principal, grant, server inventory, per-server tool, and aggregate catalog collection filters and sort/direction pairs have closed destination-specific schemas; direction requires a sort. Server sections accept `status`, `tools`, `operations`, `authentication`, and `settings`; `activity` and `overview` are invalid tab values. Only the tools and operations projections accept their declared collection filters/sorts; other sections and create destinations reject undeclared members. Serialization orders destination-specific selectors first (create IDs, queue, tab, sort, direction), then filter keys alphabetically, retaining explicit sort/direction values. Initial, invalid, and noncanonical locations use `history.replaceState`, while accepted navigation retains browser Back/Forward behavior.

Rejected text is never rendered or diagnosed, and signed-out fallback is fixed at `#/sign-in` (`#/overview` is reserved for authenticated fallback). Theme persistence is owned only by `theme.ts` under the canonical `agent_gateway_theme` localStorage key with `system`, `light`, or `dark`. A valid canonical preference wins; otherwise a valid `mcp_gateway_theme` value supplies the preference and is migrated. The legacy key is removed only after successful canonical persistence, including when the canonical preference already wins. Failed persistence retains the legacy preference and the selected in-memory presentation; a subsequent load can attempt migration again. Invalid values are never rendered and default to `system` when neither key is valid; malformed canonical state is removed when storage permits. Unavailable or throwing storage access leaves the UI usable with the system default, and explicit theme changes remain usable in memory without a persistence guarantee. Legacy malformed state may remain until a valid canonical preference is persisted. The application creates no sessionStorage, IndexedDB, Cache Storage, or service-worker state.

### Session and read lifecycle

`session.ts` validates bootstrap and problem envelopes from unknown values, accepts the prior context-free `invalid_server_configuration` envelope during client/Gateway version skew, and owns exchange, bootstrap, logout, and monotonically increasing authentication epochs. Epoch changes abort tracked requests/streams, cancel timers and polls, clear registered protected state, discard late results, and never replay a mutation; one coalesced bootstrap settles session loss.

The masked sign-in field has no reusable credential name or value attribute, clears before awaiting exchange settlement, and never publishes the bearer or in-memory CSRF value. `view.ts` binds panel reads to that epoch plus the canonical location and a monotonic view generation, aborts and discards superseded reads, preserves only matching prior values as explicitly stale, isolates panel failures, groups equal-interval visible polling, and pauses polling while hidden.

Overview is a readable operational dashboard with at most seven surfaces, in stable DOM and keyboard order: Gateway readiness, Storage and material, Work capacity, MCP attention, Pending MCP decisions, one shallow MCP inventory widget, and a secondary Recorded activity band. Neutral boundaries and strong text/numbers establish hierarchy; state accents describe observed evidence, never decorative success. Desktop uses available width with three initial columns, then attention/decisions, inventory and activity; narrower layouts stack before content becomes cramped. There are no whole-card links, per-widget Refresh controls, animated counters, global Healthy/access score, summed utilization, or ornamental feed.

The six core widgets reuse system posture, bounded server traversal (including one stale-cursor restart), and one pending-request page. Each source retains local loading, stale, error, and completeness evidence; widgets sharing a source share freshness and announcements. Compatible stale values are explicitly last known with current state unknown; loading/unavailable are nonnumeric. Process, Administration API, MCP ingress and HTTP proxy readiness are admission capability, not downstream reachability or effective access. Absent optional facts are Not reported and disabled components are neutral. SQLite/latch, traffic-store posture, keyring startup capability, HTTP CA capability and backup context remain distinct: startup is not a fresh credential probe, CA capability does not establish client trust, and backup completion is not recovery assurance. Authoritative latch status still closes mutation admission. Fallback-prone durable occupancies/traffic byte measurements do not support affirmative headroom claims.

Work capacity shows directly measured MCP work, downstream dispatch, HTTP connections and HTTP work separately. Backend saturation precedes integer-safe 80% pressure in an at-most-three exception preview with an additional count and Resource limits link. Preserve zero-limit N/A, above-limit numeric evidence and large integer precision; never sum independent pools. MCP attention shows the scoped count and at most five named servers in authoritative list order, each with one specific observed reason and direct Status link. Only complete current traversal supports exhaustive counts; loaded/incomplete/last-known qualification stays beside emphasized counts. No flagged server is not global health. Inventory shows Configured MCP servers and Active MCP catalog tools from that same traversal, not authorized/callable tool counts. One bounded `/api/v2/mcp/catalog?limit=1` read enriches this widget with independently fresh catalog state/issues/generation; catalog issues are neither failures nor affected-server counts.

Pending MCP decisions shows the exact validated `total_count` and oldest-five requester/target/waiting-time/Review preview from the same queue response, including its recognition labels, zero offset and cursor/row coverage. Never substitute independently refreshed sidebar totals, derive the total from five rows, timestamp-sort the preview or adjudicate inline. The sidebar retains its own existing read owner.

Recorded activity uses one authenticated bounded summary read, not sampled history scans or browser-accumulated pseudo-history. The existing grouped visible view owner supplies its 30-second cadence, hidden pause, navigation/session cancellation, late fences and source-local error/stale preservation; there is no competing timer, stream, authentication or mutation-retry owner. The secondary band labels MCP calls, HTTP requests and CONNECT separately, with last-15-minute recorded admissions, known recorded failure completions, refusals and unknown completions in aligned compact metrics and named history links. Exact per-minute evidence remains in a disclosure; no unlabeled miniature trends are shown. Explicit epoch/start/as-of/bucket/window bounds and complete/partial/unavailable coverage prevent pre-collection or reset gaps from becoming zeros. Admissions and terminal writes settle at separate event times: subtraction is not in-flight, missing completion is not success, and zero failures is not success or safe-replay evidence. History/detail interpretation and retry safeguards remain with their owning destinations.

The invocation destination applies closed authoritative fragment filters, serializes one filter-bound traversal with stale-cursor restart, presents user-facing tool and linked identity evidence, and renders fixed-redacted arguments only on item detail as inert JSON. Explicit live mode refreshes from committed ID-only invocation invalidations, while paused mode keeps the displayed snapshot stable; missing-terminal and evicted evidence never imply nonexecution, downstream handoff for local targets, automatic replay, or safe retry.

System labels serving readiness independently of optional history and diagnostic delivery. A history or stderr failure leaves the serving verdict intact, with local safe inspection guidance and policy-only preview navigation, never execution/replay actions. Database/WAL/free-space failures display Unavailable, absent WAL displays Absent, and pruning accounting is not rendered as zero after a failed read. Queue records, byte reservations, completion pressure, cumulative delivery/loss and last successful diagnostic write remain payload-free. A secondary process-observation disclosure explicitly separates HTTP requests, their Git subset and CONNECT, pipeline results and untrusted Git reports; it preserves process epoch, saturation and unknown crash/missing-terminal coverage. The existing recorded-activity surface and historical query populations are unchanged.

The System status panel reads only on System Status and Resource limits destinations; the independent session-wide mutation-latch read remains active elsewhere. Hidden System panels must not duplicate that read or compete with visible history for bounded traffic readers. System status strictly projects every process, SQLite, keyring, backup, protocol, and closed limit fact, closes global mutation admission from the authoritative latch, and presents stopped-process-only initialize, authority reset, current-integrity verification, and verified-backup restore command boundaries without online execution or commit/rollback inference. ### Table conventions

All Gateway tables follow one shared visual and accessibility system. Choose the layout by the reader's task, not by whether the data refreshes live:

- **Activity:** when, what happened, who/what it involved, and the result. Put the event timestamp first; identify the row by the activity, not the timestamp. Default to authoritative newest-first chronology.
- **Resource:** identity, relationships/scope, status or policy, attributes/counts, dates, then actions. Named inventories default to name ascending; grants explicitly select description ascending. Chronological work queues are the exception: Requests put Submitted first, with Pending oldest-first and All requests newest-first. Server tools retain last-seen descending; credentials and backups retain creation descending.
- **Comparison:** retain a horizontally scrollable table when cross-row numeric comparison is the primary task, as for resource limits. This is a responsive exception, not a third domain-column convention.
