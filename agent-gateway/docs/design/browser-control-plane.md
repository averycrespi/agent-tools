# Browser Control Plane

Audience: Maintainers changing the administrative browser

Authority: Normative product design

This chapter owns browser state, workflows, presentation and secret sinks. [Administrative control plane](administrative-control-plane.md) owns server-side sessions, HTTP administration and CLI authority; [frontend development](../maintainers/frontend-development.md) owns implementation and verification procedures.

## HTTP credential administration

HTTP > Credentials is a distinct navigation group and operator surface at `#/http/credentials`, with `new` and credential-ID suffixes. It uses the shared session, collection, invalidation, mutation, dirty-form and write-only-sink owners. List/detail show identity, HTTPS boundary, safe header recipe, material availability and referencing grant IDs; no stored-secret reveal exists. Create/edit review the proposed scope and recipe; the service canonicalizes and validates them. Rotate/delete require consequence confirmation. Secret fields clear on submission, cancellation, navigation and session loss. Errors remain local; uncertain outcomes block replay and require inspection. A referenced credential cannot be deleted. Grant references link to the HTTP grant detail. Traffic history is a separate read-only surface, not a proxy listener.

## HTTP traffic history

HTTP > Traffic (`#/http/traffic` and record-ID detail) is separate from MCP
Invocations, HTTP Grants and administrative audit. Lists use exact principal-ID,
destination hostname, type, decision and outcome filters. The shared table shows
only admission time, safe destination/method, principal, type, decision and outcome;
principal labels come from the existing batched directory. Detail shows immutable
admission-time references, default, selected material generation and expandable
matched selectors, never a reconstruction from current authority. Opaque tunnels
promise no inner-request visibility. Missing terminal evidence does not prove
nonexecution or safe retry. There is no traffic-to-grant shortcut.

The shared protected view/session owner fences navigation, refresh, and logout.
Live starts on; Load older pauses automatic replacement and retains up to 500
records in 50-record pages, with explicit Resume live/Return to newest. Turning
Live off persists only in memory until session loss. Manual refresh replaces the
loaded window without enabling Live. Expired shared cursors restart at newest
with an explicit notice; other read failures preserve prior evidence with a stale
warning. HTTP uses existing coalesced System traffic invalidations rather than a
per-record stream. Exact filters and detail links survive Back navigation but no
cursor or evidence is placed in the URL or browser persistence.

## HTTP grant administration

HTTP > Grants (`#/http/grants`) uses the shared authoritative table filters/sorts, snapshot pagination, session/view refresh and mutation owners. `new`, grant-ID and `test-access` suffixes are closed locations. Principal detail exposes HTTP default in the consolidated Edit principal card. One Save principal PATCH contains only dirty identity/state/visibility/default fields and uses the unified principal ETag. State or default changes require one combined confirmation of all proposed changes; cancel sends no mutation. Conflicts preserve drafts and require deliberate review of refreshed values/revision. Unknown outcomes cannot be replayed; navigation remains guarded while a draft is dirty. The grant table orders Grant, Principal, Destination, Type, Status and Expires and reflows through the shared narrow-table primitive.

One adaptive form edits all four explicit types: principal, description, destination and expiry are common; request types add scheme, method rows and path match; allow types expose local/private consequences; only request allows offer whole-scope-compatible HTTPS credentials. Tunnel selection prominently warns of opaque request-policy and injection bypass. No wizard, HTTP self-service request, traffic shortcut or agent-first MCP redesign exists. Drafts/previews are bounded, session-local and never browser-persisted. Exact ETag conflicts require fresh inspection and explicit reconfirmation; uncertain changes have no replay path.

Test access selects principal and request URL/method or explicit CONNECT host/port, calls the actual policy evaluator once, and displays deciding default/grants, transport, credential conflicts and local-access requirements. Network/TLS/material are explicitly unverified; the response confers no future admission authority. Preview targets never enter browser locations, audit, events or logs.

## Browser development boundary

The frontend development path is build/test-only and uses a second independently managed numeric-loopback Vite process. It serves authored source and local HMR, admits only segment-bounded `/api/v2/` traffic to one fixed numeric-loopback Gateway origin, rewrites only the exact frontend Origin, and preserves the host-only cookie/CSRF boundary without adding production CORS or alternate-Origin authority. It never supervises Gateway, proxies `/mcp` or `/oauth/callback`, writes the embedded asset directory, or enters the production import graph; OAuth callback authority remains at Gateway. The operational contract is documented in [frontend development](../maintainers/frontend-development.md).

## Browser state and workflow ownership

### Production assets and navigation

The developer control application is built from strict TypeScript and Preact with Vite into a fixed embedded HTML, stylesheet, and module allowlist. The checked-in bundle contains no external or inline active content, source maps, chunks, or runtime Node dependency and uses the fixed restrictive CSP.

The application is branded **Agent Gateway**. Primary navigation separates shared administration from the MCP domain: **Overview**, **Principals**, **Audit Log**, **System** in one unlabeled group; then **HTTP** (Credentials, Grants, Traffic) and **MCP** (Servers, Tools, Grants, Requests, Invocations). Groups are not new destinations or domain editors. MCP collection page titles include their protocol: **MCP Servers**, **MCP Tools**, **MCP Grants**, **MCP Access Requests**, and **MCP Invocations**. Creation titles are **Create MCP Server** and **Create MCP Grant**. Sidebar and tab labels remain short; **Audit Log** matches its navigation label. Invocations needs no explanatory subtitle and presents only existing MCP invocation evidence, separately from Audit Log; no additional protocol coverage or placeholder is implied. These are history destinations, not identity directories. Audit Log retains all existing audit attribution, including system and offline maintenance events; its label is not an actor filter. Overview remains shared, with protocol-specific summaries labeled MCP. System traffic storage reports the shared MCP/HTTP budget, fault and pruning boundary, not new per-protocol metrics. Desktop and narrow disclosure navigation share the same ordered links, current-destination semantics, keyboard handling, and state owners.

One closed domain-grouped hash grammar owns browser locations: `#/mcp/servers`, `#/mcp/tools`, `#/principals`, `#/mcp/grants`, `#/mcp/access-requests`, `#/mcp/invocations`, `#/audit-log`, `#/http/credentials`, `#/http/grants`, `#/http/traffic`, and `#/system`. Overview and sign-in remain `#/overview` and `#/sign-in`. Detail and create suffixes remain beneath their owning collection; server-owned `operations/{id}`, `auth-flows/{id}`, and `descriptors/{id}` remain beneath `#/mcp/servers/{id}`. System create destinations remain unchanged. Retired `#/access/principals`, `#/activity/audit`, `#/access/grants`, `#/access/requests`, `#/activity/invocations`, and other undeclared paths are invalid, with no aliases or redirects. Principal detail/create and audit detail suffixes follow their canonical collection; this browser location cleanup changes no API endpoints. Invalid locations retain the safe fixed fallback and navigation notice, never a resource lookup or mutation inferred from the rejected path. No pathname fallback serving is introduced. See the [operator location mapping](../operators/upgrade-compatibility.md#browser-location-cutover). Location naming does not change the shared theme owner, session epochs, refresh/pagination, mutation coordination, or one-time-secret sinks.

Its manual fragment parser accepts only ASCII `#/` locations up to 2,048 bytes from the closed destination table, canonical Gateway IDs, and destination-specific filters. It rejects path percent escapes, controls, empty/trailing segments, duplicate or unknown keys, cursors, unapproved text, and unknown enumerated values before API work or rendering. Recognition filter text is percent-encoded, bounded to 256 UTF-8 bytes per value, and excludes control/format characters. Server inventory and tool/catalog filters apply these bounds to both the supplied and NFKC/lowercase forms before navigation. Principal, grant, server inventory, per-server tool, and aggregate catalog collection filters and sort/direction pairs have closed destination-specific schemas; direction requires a sort. Server sections accept `status`, `tools`, `operations`, `authentication`, and `settings`; `activity` and `overview` are invalid tab values. Status is the default and serializes without `tab=status`, as does System status. Only the tools and operations projections accept their declared collection filters/sorts; other sections and create destinations reject undeclared members. Serialization orders destination-specific selectors first (create IDs, queue, tab, sort, direction), then filter keys alphabetically, retaining explicit sort/direction values. Initial, invalid, and noncanonical locations use `history.replaceState`, while accepted navigation retains browser Back/Forward behavior.

Rejected text is never rendered or diagnosed, and signed-out fallback is fixed at `#/sign-in` (`#/overview` is reserved for authenticated fallback). Theme persistence is owned only by `theme.ts` under the canonical `agent_gateway_theme` localStorage key with `system`, `light`, or `dark`. A valid canonical preference wins; otherwise a valid `mcp_gateway_theme` value supplies the preference and is migrated. The legacy key is removed only after successful canonical persistence, including when the canonical preference already wins. Failed persistence retains the legacy preference and the selected in-memory presentation; a subsequent load can attempt migration again. Invalid values are never rendered and default to `system` when neither key is valid; malformed canonical state is removed when storage permits. Unavailable or throwing storage access leaves the UI usable with the system default, and explicit theme changes remain usable in memory without a persistence guarantee. Legacy malformed state may remain until a valid canonical preference is persisted. The application creates no sessionStorage, IndexedDB, Cache Storage, or service-worker state.

### Session and read lifecycle

`session.ts` validates bootstrap and problem envelopes from unknown values, accepts the prior context-free `invalid_server_configuration` envelope during client/Gateway version skew, and owns exchange, bootstrap, logout, and monotonically increasing authentication epochs. Epoch changes abort tracked requests/streams, cancel timers and polls, clear registered protected state, discard late results, and never replay a mutation; one coalesced bootstrap settles session loss.

The masked sign-in field has no reusable credential name or value attribute, clears before awaiting exchange settlement, and never publishes the bearer or in-memory CSRF value. `view.ts` binds panel reads to that epoch plus the canonical location and a monotonic view generation, aborts and discards superseded reads, preserves only matching prior values as explicitly stale, isolates panel failures, groups equal-interval visible polling, and pauses polling while hidden.

Overview is a compact triage page, prioritizing operational exceptions and human decisions over inventory. Independent strict public reads supply system posture, a bounded server traversal with one stale-cursor restart, and one pending-request page. Each source retains local loading, stale, error, and completeness evidence; unavailable or incomplete reads never imply current exhaustive reassurance. Normal process readiness, SQLite latch state, and keyring capability are compact explicit facts. Abnormal conditions show the observed condition, a concise consequence, and a System drill-down, not recovery instructions. Affected resources independently show occupancy/limit and authoritative saturation or integer-safe 80% capacity pressure; there is no aggregate health or utilization score. Authoritative latch status still closes mutation admission.

Overview shows at most five attention-eligible servers in server-list order, each with its name, one specific observed state, and a direct Status link. Additional loaded affected servers produce “5 shown; more need attention”; incomplete traversal warns that additional affected servers may exist. Configured-server and active-catalog-tool counts are quiet secondary context, exact only after complete traversal and otherwise labeled loaded/incomplete. Pending access requests are distinct human work: the oldest five in authoritative queue order, never timestamp-sorted, with requester, requested access, approximate waiting time, and a review link. Overflow says “5 shown; more pending”, not an aggregate backlog total; adjudication stays on the request destination.

Current complete reads with no flagged conditions or pending decisions yield brief source-specific reassurance and unused space, not global health claims, hero inventory cards, ornamental codes, or routine activity. Global destinations remain in the primary navigation rather than a redundant Overview footer; contextual condition and preview links retain direct drill-downs, including resource limits and individual request review. Overview performs no invocation reads or polling and does not infer alerts from sampled invocation evidence; history/detail evidence interpretation and retry safeguards remain owned by the invocation destination.

The invocation destination applies closed authoritative fragment filters, serializes one filter-bound traversal with stale-cursor restart, presents user-facing tool and linked identity evidence, and renders fixed-redacted arguments only on item detail as inert JSON. Explicit live mode refreshes from committed ID-only invocation invalidations, while paused mode keeps the displayed snapshot stable; missing-terminal and evicted evidence never imply nonexecution, downstream handoff for local targets, automatic replay, or safe retry.

System status strictly projects every process, SQLite, keyring, backup, protocol, and closed limit fact, closes global mutation admission from the authoritative latch, and presents stopped-process-only initialize, authority reset, current-integrity verification, and verified-backup restore command boundaries without online execution or commit/rollback inference. Server inventory, per-server tools, and aggregate catalog render one server-selected page of at most 50 rows, with shared accessible Previous/Next controls and no automatic fetch-all or appended inventory. They reuse the location/session/visible-refresh and pagination owners used by principals and grants, but show only the number of rows on the current page, without totals. All filters and sortable columns operate across the full collection. Server fields are name/ID, namespace, and synthesized status, with name/ID/namespace/status/active-tool-count sorting; per-server tools filter by external tool name and available/retired status, with tool/status/last-seen sorting; catalog filters use tool/server names and available/catalog-issue status, with tool/server sorting. Status is evidence, never a permission or callability assertion.

All Previous/Next collections follow [collection pagination](#collection-pagination). Backend cursors retain their distinct inventory-watermark/observed-fact, descriptor-revision and active-generation guarantees.

### Table conventions

All Gateway tables follow one shared visual and accessibility system. Choose the layout by the reader's task, not by whether the data refreshes live:

- **Activity:** when, what happened, who/what it involved, and the result. Put the event timestamp first; identify the row by the activity, not the timestamp. Default to authoritative newest-first chronology.
- **Resource:** identity, relationships/scope, status or policy, attributes/counts, dates, then actions. Named inventories default to name ascending; grants explicitly select description ascending. Chronological work queues are the exception: Requests put Submitted first, with Pending oldest-first and All requests newest-first. Server tools retain last-seen descending; credentials and backups retain creation descending.
- **Comparison:** retain a horizontally scrollable table when cross-row numeric comparison is the primary task, as for resource limits. This is a responsive exception, not a third domain-column convention.

The column inventory is:

| Table             | Ordered columns                                                                        |
| ----------------- | -------------------------------------------------------------------------------------- |
| Servers           | Server, Namespace, Status, Active tools                                                |
| Available tools   | Tool, Server, Status                                                                   |
| Server tools      | Tool, Status, Last seen                                                                |
| Principals        | Principal, Status, Visibility                                                          |
| Grants            | Grant, Principal, Target, Effect, Status, Conditions, Expires                          |
| Requests          | Submitted, Request, Principal, Target, Status, Requested duration, Conditions, Actions |
| Invocations       | Admitted, Invocation, Principal, Authorization, Outcome                                |
| Audit             | Time, Event, Performer, Target, Outcome                                                |
| Server activity   | Created, Operation, Status, Reason                                                     |
| OAuth activity    | Created, Flow, Status, Reason                                                          |
| Admin credentials | Credential, Status, Created, Expires, Actions                                          |
| Backups           | Backup, Source, Size, Created, Actions                                                 |
| Resource limits   | Resource, In use, Limit, Used (%), Status                                              |

Resource limits derive **Used (%)** from the same status snapshot as In use and Limit, with right-aligned numeric text and at most one decimal place (no trailing `.0`). Zero limits display **N/A**. Below-capacity values that would round to 100% display 99.9%; genuine above-capacity values are not capped. Calculation preserves all nonnegative safe integers accepted by the status decoder, including percentages larger than the safe-integer range. Status and styling remain backend-authoritative, with saturated rows first; percentages add no thresholds, visualization, or requests.

**Identity and navigation.** Put the human-recognizable label first, followed by the complete muted monospace ID where identity is needed. Servers and principals use display names, grants use descriptions with an explicit Unnamed grant fallback, credentials use fingerprints, and generic requests/backups/flows use explicit record-kind labels. Tool catalogs need not repeat descriptor IDs already available in detail. Primary record links have one shared emphasis; related-resource links remain ordinary links. Audit Event links to event detail. The Invocation column uses the tool name as its readable primary label, retaining the downstream descriptor link. Its secondary ID is displayed without a prefix and separately links to invocation detail with an explicit accessible name. The Tool filter still searches recorded tool names, not invocation IDs. Do not add row-wide click handlers, redundant Open/View buttons, or per-row identity lookups. Row controls belong in trailing **Actions**; pending Review is prominent, destructive controls remain distinct, and absent actions use an em dash rather than an implementation state such as Terminal. Actions stay pinned to the right edge of a horizontally scrolling desktop table so reviewing a queue never requires finding an off-screen control; stacked narrow rows reset that positioning. The shared scroll region reserves the pinned width and brings focused controls into the unobscured viewport, including at intermediate desktop widths.

**Vocabulary.** Use **Status** for lifecycle/availability, **Outcome** for observed event results, **Reason** for explanation, **Effect** for Allow/Deny policy, and **Authorization** for invocation admission decisions. Reserve **Actions** for controls, not recorded operations. Use **Conditions** for user-facing policy restrictions, **Expires** for expiry timestamps, and **No expiry** for absent expiry. Retain precise timestamp meanings: Admitted, Submitted, Created, and Last seen are not interchangeable. Column/filter terminology agrees, allowing identity filters to clarify searchable names, descriptions, fingerprints, or IDs. UI labels do not rename wire keys or reinterpret Available as permission/callability.

**Sizing and cell content.** Keep full names, targets and IDs recoverable without hover-only tooltips or JavaScript truncation. Long descriptive values wrap; identifiers remain selectable. Numeric cells align right, multi-line rows align at the top, and localized timestamps retain their exact instant. The [table implementation](../maintainers/frontend-development.md#table-implementation) owns component roles, CSS sizing and formatter mechanics.

**Status colors.** Green/current denotes positive active/available/succeeded evidence, loading denotes ongoing machine work, warning denotes attention or uncertainty, and error denotes observed failure. Neutral denotes disabled, retired, revoked, expired, cancelled, superseded, or deliberately rejected/denied states; terminal does not mean successful. Pending human review remains warning. Invocation authorization uses the shared status label: Allow is green/current; Deny, Block and Not evaluated are neutral, matching policy-refusal outcomes rather than suggesting execution errors. The same authorization presentation applies in invocation detail. Retain explicit text and distinguish an interrupted/unknown outcome from known failure. Apply the same mapping to corresponding detail badges.

**Queries and responsive behavior.** Preserve each domain's read owner: full-collection Previous/Next pagination, complete local collections, and append-older history are not interchangeable. OAuth's loaded-row filters/sorts explicitly disclose their scope. Counts distinguish matching totals, current-page counts, and loaded history; never invent totals. Keep live/pause and refresh controls above the table and preserve older-reading pause and snapshot semantics. Visible column headers own desktop sorting; do not duplicate them with a separate sorting toolbar. Merged identity columns do not expose dedicated ID-sort options, but legacy ID-sort URLs remain supported. Operation tables explicitly request creation-time ordering; legacy started-or-created sort URLs retain their original meaning.

Below 700px, resource and activity rows become labeled stacked records in unchanged reading order; comparison tables keep horizontal scrolling. Keep complete values, actions, and query controls reachable without document overflow. A shared sort selector and direction button appear only when column-header controls are hidden, offering the visible columns. A legacy non-column sort restored from a URL is identified as Custom order rather than silently showing another column. Query changes use the existing owner and preserve applicable URL/history semantics. Tables retain captions, explicit column labels, semantic row headings selected by identity key rather than position, and a keyboard-focusable scroll region. Verify both table families with long values, populated/empty/error states, desktop/narrow/320px widths, light/dark themes, keyboard sorting, and real-browser accessibility checks before changing these conventions.

### Collection pagination

Previous/Next collections, including embedded consumers, show one server-selected page, never fetch-all or appended inventory. Filters and Reset occupy the first control row; navigation and the right-aligned range summary occupy a second wrapping row. Repeat navigation/summary below the table with distinct accessible region labels and shared query/cursor/loading state; only the top summary announces. Each action advances one page. Unpaginated tables and Load older history do not acquire these controls.

Principals and grants show at most 50 rows. Their response supplies snapshot-consistent `offset` and exact matching `total_count`, accepted together with rows: “Showing 51–100 of 128 grants”, with singular names where appropriate. Zero results distinguish empty inventory from no matches; loading/failure show “Loading…”/“Unavailable”, never an old current count. Server inventory/catalog/tools instead show current-page counts, not totals. Filters and deterministic sorts select across the complete bounded recognition snapshot with ID-ascending ties. Grant projections supply principal/server labels without browser traversal.

Closed destination-specific `filter_*`, `sort` and `direction` values live in the fragment; direction requires sort. Principal filters are `filter_name`, `filter_state`, `filter_visibility`; grant filters are `filter_identity`, `filter_principal`, `filter_target`, `filter_effect`, `filter_state`. Query changes restart page one; Back/Forward restores the query, while shared links and reloads start fresh. Invalid/oversized drafts give local errors without navigation. Focus and usable filters survive refresh and zero results.

Cursor history stays session-local, never in URLs or browser storage. Query generations and authentication epochs abort/fence superseded reads. A stale non-first-page cursor discards history and attempts page one once with a notice; a failed/stale first page remains an error, not a loop. Manual/event refresh retains the query; session replacement clears history and response data. Legacy API defaults and representations remain compatible.

### Request decisions

Requests composes the shared remote collection owner: Pending defaults to oldest submitted first, All requests to newest first. Closed fragment keys are `queue=all`, `filter_request`, `filter_principal`, `filter_target`, `filter_scope`, `filter_state` (All requests only), and sort/direction. Controls apply before bounded pagination; no browser-wide identity traversal or per-row detail reads supply queue names. Exact requested-target identity and readable access summaries stay distinct from later approved authority. The trailing Actions column contains Review/View decision links; the primary Request link opens the same detail and the full searchable ID remains secondary identity text.

Pending detail presents named authority, approval-relative duration, readable conditions, and tool-definition posture without repeated general access warnings before the three paths: Approve as requested, Customize approval, Reject request. Direct approval confirms requested authority without the editor. Narrowing uses the existing matcher-validation and token-preserving editor owners, locked submitted atoms, additive AND conditions, and a live Approval preview of requested/proposed values. Customization toggles without discarding edits; direct unchanged approval never incorporates the hidden draft. Confirmation distinguishes unchanged from narrowed authority, exposes exact identifiers and serialized policy, and rejects a changed reviewed draft. Rejection has a separate reason dialog and never validates approval fields, revokes access, or creates a DENY.

Technical identifiers and inert descriptor evidence live under accessible native disclosures; absent evidence cannot imply no drift, and server-to-tool narrowing compares like-for-like approved evidence. Acknowledged terminal outcomes have outcome-specific page titles, a Created grant link immediately under Approved decision, explicit queue return, and optional next-pending navigation. The created-grant field records the historical result without asserting present authority or repeating a disclaimer. Returning within the Requests destination retains query and cursor context and revalidates it. Opening the next request reads its current state; there is no automatic advance. Concurrent settlement resets revision-bound decisions; uncertain outcomes remain local and persistent across refresh without success or replay. Existing session, navigation, mutation, storage-latch, and duplicate-submission owners remain authoritative.

### Invocation history browsing

Failure diagnostics use one compact panel: Gateway-observed source/reason remains distinct from a clearly scoped, once-labeled unverified server report. Meaningful errors and masked field paths lead; schema/version, rule, code, secondary classification, and masking explanation remain available in collapsed native Technical details. A concise duplicate-effects warning accompanies failures with possible execution, not pre-start failures; diagnostics add no retry action or execution authority. Captured arguments render populated captures as inert JSON, `{}` as **Captured arguments · Empty**, and absent or truncated captures as distinct states. General redaction limitations belong in the [operator evidence guide](../operators/invocation-evidence.md#understand-redaction-and-retention), not a persistent capture disclaimer.

The Invocation table links resolved downstream tool labels to descriptor details using recorded server/tool IDs, matching Invocation detail behavior. Unresolved and Gateway-local tools remain plain text. Links preserve historical labels and do not imply current resource availability; no name-based lookup or per-row availability request is added. Search semantics remain in the query contract and operator guidance rather than permanent explanatory prose beside the controls.

Invocation Tool, Principal, Authorization and Outcome controls send the closed `filter_tool`, `filter_principal`, `filter_decision` and `filter_outcome` fragment query to the authoritative history API. Text drafts apply through the existing 300 ms input owner; selects and Clear filters apply immediately. Invalid drafts never publish a query. Controls remain present during initial loading, empty results, refresh and failure; only a successful authoritative query establishes no matching invocations. Applied filters remain visible and clearable. The [public query contract](public-contract.md#invocation-history-queries) owns bounded fuzzy matching and the distinction between recorded tool/identity evidence and current principal recognition names.

Live preference and older-reading pause are independent session-local state. At newest with Live on, the existing coalesced invalidation owner refreshes the newest page under the current query, including a previously empty filtered view. A live refresh replaces the traversal, never appends an older snapshot. Load older establishes pause before starting its one continuation. With Live on, paused browsing displays Live paused while viewing older results and Resume live; Live off still permits explicit reads. Resume live (or Return to newest while off) discards the previous traversal and clears pause without enabling a disabled preference. Manual refresh restarts newest without enabling Live; changing or clearing filters restarts newest without clearing pause or changing preference. Known invalidations while paused/off may indicate Updates available, never an unverified matching arrival. Automatic refresh eligibility is rechecked by the shared view owner when coalesced or reconnect work executes; superseded/in-flight automatic results cannot override a later pause or Live-off choice.

Detail links carry only the applied query, not cursors. Returning or browser Back/Forward revalidates the newest matching page with the same Live/off/paused context and explicitly reports that the previous traversal was discarded. Direct detail entry returns to an unfiltered newest page unless its link supplies a valid query. Session replacement clears all data, preference/pause and traversal state; no opaque cursor, authority, or persistent history cache enters URLs or browser storage. Focus stays in controls during query refresh and compatible content remains during background reads.

A failed continuation retains valid loaded rows and a local read-only retry/error beside Load older. Failed fresh/live reads retain only compatible query data, explicitly stale, and never show false empty success. A stale cursor discards the incompatible traversal before one fresh read; failure retains the restart notice, not old-snapshot pages. Counts say how many invocations are loaded, not an implied history total. Clear filters and Resume live are separate actions.

### Audit clients

Audit Log is the shared read-only administrative audit destination in the unlabeled gateway-wide group, separate from Invocations and Requests under MCP. Its API `/api/v2/audit-events` and `audit` CLI remain unchanged; the label imposes no actor restriction or protocol filter. Its closed `filter_*` fragment vocabulary maps directly to the authoritative audit API filters, including paired fixed-nanosecond UTC bounds. From and Until use local-timezone datetime pickers; the client converts selections to the API's UTC format and preserves unchanged precise bounds restored from a fragment. Paired-bound, ordering and 366-day range failures receive plain-language validation. Dropdown changes apply immediately, IDs after a 300 ms pause, and dates only as a complete valid pair. Draft fields stay separate from the applied query: invalid IDs or date drafts neither replace results nor block independent valid dropdown changes. A changed draft shows the value still used by current results beside its field; settled fields do not repeat the applied query in a separate paragraph. Category changes clear incompatible actions atomically. Clear filters immediately clears drafts and applied filters. A compact wrapping toolbar keeps Category, Action, Outcome, From and Until visible. Add filter offers actor type, credential ID, target type, target ID and correlation ID; selecting one inserts its labeled field and focuses it. Each optional field has a Remove control that clears both draft and applied value and returns focus to Add filter. URL-restored filters appear automatically, including on browser history navigation. Keep credential-matching help and validation beside the relevant field; do not hide them under a More filters disclosure. Applied query and browser history changes restart page one; no loaded-row filtering or sorting substitutes for server selection. The page composes the existing location, session, view-coordination, form, table, time, focus and notice owners. Manual refresh and stream reconnection restart the newest matching page; Audit adds no polling, stream, persistence or authentication owner.

Load-older traversal retains the opaque cursor and generation only within the authenticated session. Stale-cursor recovery first discards the previous traversal, then attempts a fresh first page once, preserving the restart notice on failure. Generation mismatch discards incompatible page/detail state and warns that restore may have discarded newer local events. Item requests pin the last observed generation; mismatch never silently opens the same ID in replacement history. Reload and session replacement clear the comparison baseline. Event links carry the applied query through the existing closed location grammar, and Back to audit history restarts the newest matching page with that query. No traversal or position is restored across a list/detail navigation because the current owner cannot safely revalidate a retained multi-page traversal. Direct event entry without query returns to unfiltered history. The oldest-retained boundary and pruning state remain separate from generation. Compact bounded/nonpermanent retention context and pruning warnings remain visible below primary content; an accessible disclosure holds technical generation and boundary facts. Load older availability communicates traversal progress without routine end-of-traversal disclaimers. Matching failed-refresh data is explicitly stale and potentially partial; superseded location/session results cannot publish. Failed Load older reads retain earlier valid rows and expose a local retry/error beside that control without marking those rows globally unavailable.

Summary/detail projections validate closed values, IDs, decimal-string sequences, attribution, limits, ordering and exact member sets before presentation. System initiators are separate from performers. Lists use the [table column inventory](#table-conventions), with event identity together in Event, phase secondary under Outcome, and sequence retained only in detail and continuity validation. Pending is neutral, failed error, unknown/rejected warning and succeeded success in both list and detail. Full identities wrap; narrow audit rows reflow with field labels. Supported server, principal, grant and request list targets link without per-row discovery; known deleted/unavailable and unsupported targets remain plain text, while unknown existence is resolved at the destination. Detail exposes only the bounded reason/problem shape and retains verified-current-target links; unavailable target reads do not suppress historical evidence. Unfiltered empty results say No audit events yet with bounded-retention context; filtered empty results say No matching audit events and offer Clear filters, never implying globally empty history. `audit list` and `audit get AUDIT_EVENT_ID` use `internal/controlclient`, preserve strict API JSON, support explicit generation pinning, and return one page or item without automatic retry. The operator interpretation and recovery procedure is owned by [Control-plane audit history](../operators/administration.md#control-plane-audit-history).

### Server workflows

The server inventory presents identity, a synthesized plain-language status, available-tool count, and the next useful action through the shared filterable and sortable responsive collection primitive; implementation revisions and reason codes remain absent. A server is organized into Status, Tools, Operations, Authentication, and Settings. The shared server context presents only the display name and one concise synthesized status.
