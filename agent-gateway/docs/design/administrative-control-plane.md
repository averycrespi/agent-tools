# Administrative Control Plane

Audience: Maintainers changing administrator authority, HTTP and CLI control, events, and shutdown

Authority: Normative product design

This chapter owns server-side administration and CLI authority. The [browser control plane](browser-control-plane.md) owns client lifecycle, workflows, presentation and secret sinks. [Public contract](public-contract.md) owns wire shapes; operator procedures remain in the linked guides. `internal/contract` supplies the corresponding executable values.

## Administrative authority and sessions

Admin bearer creation uses 32 bytes of entropy and the fixed `mgw_admin_` domain prefix. SQLite stores only a domain-separated SHA-256 verifier, a separately domain-separated 16-character fingerprint, metadata, status, and revision. Authentication distinguishes the reserved agent prefix before performing constant-time verifier comparisons; unknown and malformed admin values remain non-enumerating.

Mutating `init` and `maintenance reset-admin-credentials` require stopped-process ownership. They complete an approved one-time sink before entering the latched security mutation. Initialization activates only an empty authority set. Reset revokes every prior active verifier and inserts one replacement in the same revisioned transaction. Sink failure leaves all persisted authority unchanged, while an activation failure cannot make an unpublished bearer usable. Command JSON, standard error, argv, logs, and SQLite never contain the raw bearer.

Credential creation validates optional expiry against the compiled five-minute and one-year bounds before consuming entropy. Metadata reads derive expiry from the injected clock; authentication compares all active verifier candidates in constant time and rejects expired, revoked, unknown, malformed, and wrong-domain values safely. Revocation transactionally preserves at least one active non-expiring authority. At the 128-record cap, creation/reset prunes the oldest revoked or expired records by creation time and ID; it rejects without queuing when every record remains active.

Online `admin credential rotate OLD_CREDENTIAL_ID` captures the authority generation, conditionally creates one non-expiring replacement, publishes it through a fresh owner-only file with file and parent-directory durability, securely reopens it, matches metadata/fingerprint, and authenticates it before submitting one conditional targeted completion with the replacement bearer. It then verifies old, replacement, and authority records. It never overwrites the default bearer, compensates, or replays. Pre-verification workflow failures preserve old authority; once publication and replacement authentication succeed, a conflict or uncertain completion may safely leave both credentials active. One bounded old-record read may recognize a completed uncertain revoke; otherwise recovery uses the retained replacement file and metadata guidance.

Bearer exchange reserves one of 128 in-memory session slots before generating independent 32-byte session and CSRF values. Sessions use a host-only `agent_gateway_session` cookie with `Path=/`, `HttpOnly`, and `SameSite=Strict`; no `Domain` is present, and `Secure` is omitted only for the fixed plain-loopback transport. Activity refreshes the 24-hour idle bound without extending the seven-day absolute bound. Exact-Origin `POST /api/v2/admin-sessions/current` accepts exact `EmptyObject` `{}` and returns `AdminSessionBootstrap`, recovering the in-memory CSRF and refreshed expiries from one current cookie without reissuing it; malformed, duplicate, unknown, expired, revoked, reset-invalidated, and restart-invalidated cookie authority is cleared with the exact expiry cookie. Logout, idle/absolute or parent expiry, parent revocation, reset, and shutdown remove the slot and synchronously close its subscription channel. Ambiguous bearer-plus-cookie authority and incorrect session-bound CSRF fail without changing activity. No session state survives manager or process restart. The legacy `mcp_gateway_session` cookie is never read as authority or translated into a canonical session. After early Host/Origin and route/method validation, exact-Origin sign-in, bootstrap, and logout responses expire a supplied legacy cookie at its original host-only `Path=/` scope, including authentication failures; deletion has `HttpOnly`, `SameSite=Strict`, `Max-Age=0`, a past `Expires`, no `Domain`, and the same plain-loopback Secure policy. A valid canonical cookie alone selects the session when both names are present; an invalid canonical cookie cannot fall back to legacy authority. Old-only browsers must sign in afresh, using the existing signed-out/version-skew recovery with no automatic mutation replay. A cancelled or deadline-exceeded parent-credential read rejects that authentication/bootstrap attempt without closing an otherwise live session; a cancelled sweep likewise supplies no revocation evidence. Fresh attempts still recheck parent authority, expiry, and CSRF, and explicit revocation/shutdown still closes sessions.

## HTTP administration

`serve` verifies stopped-process ownership and storage, takes one secret-free keyring capability snapshot, and only then opens the exact configured numeric IPv4 loopback listener. The boundary validates request target, header, forwarding, Host, Origin, route, and method constraints before authentication or body work. Health, ordinary, control-auth, and authenticated-admin permits are independent and nonblocking; authenticated control work transfers permits without allowing ordinary traffic to consume recovery capacity.

Startup accepts repeatable hostname-only `--allowed-host` values, validated before installation or listener work. The boundary accepts the canonical numeric listener authority plus exactly those ASCII DNS-case-normalized hostnames, with no DNS-derived, suffix, or subdomain trust. The shared executable hostname grammar rejects IP literals, numeric final labels, trailing dots, empty/oversized labels, non-ASCII characters, and non-DNS syntax; labels contain letters, digits, and internal hyphens only, at most 63 bytes each and 253 bytes total. For listed names only, an absent port or decimal nonzero port up to 65535 (leading zeros permitted) does not participate in matching. Malformed authorities and ports fail before authentication. The original Host is not rewritten, and every existing route retains its classifier, method, admission, and credential authority. Host removal takes effect on restart and is independent of administrator credential revocation.

Allowlisting changes reachability only: the exact numeric listener Origin, including its port, remains the sole browser Origin. Session exchange/bootstrap and CSRF checks, no-CORS, and forwarding-header rejection are unchanged. Main OAuth callback selection and registration never derive authority from the allowlist or incoming Host. Optional per-server `callback_uri` creates only a composition-owned temporary numeric-loopback callback listener when the exact default callback is not reused. Only its configured path, GET method, and exact authority are admitted. Port conflicts fail before URL publication without fallback, and terminal/cancellation/expiry/supersession/shutdown paths close the listener. No main route or browser Origin authority is expanded.

The control API implements bearer-to-session exchange, current-session bootstrap, session logout, bounded administrator credential/authority/rotation-completion and backup resources, invalidation events, system status, desired-server create/list/read/PATCH/DELETE, operation and auth-flow resources, server credential replacement, catalog and descriptor reads, permanent principal create/list/read/PATCH with singular credential issue/revoke, immutable grant create/list/read/delete, and grant-request summary/item/approve/reject resources with exact request ETags and preconditions. Collections exclude descriptor evidence; item and adjudication responses include bounded evidence and read-time target comparison, while approval atomically creates one ordinary grant and rejection remains request-owned.

Bearer and cookie authority cannot be combined. Cookie requests require the exact configured Origin; safe GET reads may use the browser-compatible fallback of an absent Origin plus the exact in-memory session CSRF token, while unsafe cookie requests always require exact Origin, the session CSRF value, and JSON media type.

JSON parsing bounds body size and nesting and rejects invalid UTF-8, duplicate members, unknown members, and trailing input. Server creation and explicit operations use parent-authority-scoped durable idempotency; server and operation lists use snapshot cursors; server reads and mutations carry exact strong Server ETags, with required exact `If-Match` on PATCH, DELETE, and operation creation.

API responses are `no-store`, problems retain fixed safe envelopes, and no response enables CORS. Invalid server configuration problems carry one closed field/rule context and never reflect submitted values or internal error text.

## Control-plane audit coverage

Control-plane audit is separate from Invocation History and Requests. SQLite changes require audit evidence in the same supplied transaction; an API response logger is not a substitute. External filesystem, runtime, keyring, OAuth, and downstream work requires a durable attempt before handoff and a distinct correlated outcome after observed settlement. Missing outcome evidence never establishes rollback, success, or permission to replay. Successful browser sign-in/logout are operator actions; unauthenticated bearer, Origin, and CSRF failures are excluded. Pre-authentication boundary rejection remains before authentication and must not create durable writes. Browser sign-in/logout now require the existing nonqueueing storage mutation slot for audit writes; contention is a bounded refusal, not an added queue. New sessions are closed and never returned when their outcome evidence cannot commit.

The following matrix owns producer, actor and transaction boundaries. Regression provenance belongs to [implementation evidence](../maintainers/implementation-evidence.md#audit-producer-evidence), not this normative matrix.

Desired server revisions, operations and OAuth flows retain only canonical correlation and optional initiating credential metadata, never request contexts or secrets. Callback and runtime handoffs copy that bounded cause and rebind it to system work. A runtime attempt refused by the nonqueueing writer before any transaction or external effect retains its operation and uses the existing reconciliation backoff; uncertain attempts or missing outcomes are not automatically replayed. Safety withdrawal and fencing still remove unsafe routes when evidence cannot commit, but cleanup is not confirmed. Invocation terminal annotation remains a separate synchronous best-effort write and can be absent during writer contention.

Routine reads, polling, cache invalidation, session expiry, subscriber eviction, and other low-level housekeeping do not belong in Audit. Invocation admission/execution/outcomes stay exclusively in Invocation History; request submission and submitted evidence stay exclusively in Requests. An asynchronous system event must never relabel the initiating operator as its performer. Historical work with no known initiator remains unattributed rather than inferring an owner from a current credential or resource.

Producer and read/store regression provenance is retained in [implementation evidence](../maintainers/implementation-evidence.md#audit-producer-evidence); it is not release qualification.

## HTTP credential administration

`http credential list|get|create|update|rotate|delete` uses only the public control API. Create, update and rotate require strict `--file PATH`; secret argv/environment inputs are not supported. Update, rotate and delete accept an exact explicit `--etag` or one validated metadata preflight; they never refresh stale preconditions. Mutations require `--yes` consequence confirmation. Keyring/storage uncertainty remains an unknown outcome, with no retry. `http_credentials` events contain only invalidation hints. Audit category/target `http_credential` records create/update/rotate/delete/invalidate, and typed keyring effects retain their independent attempt/outcome evidence.

## HTTP grant administration

CLI `http grant list|get|create|update|delete`, `http default get|update`, and `http test-access` use the public API only. Grant writes and preview use strict `--file PATH`; default convenience files use `http_default` and route to principal GET/PATCH with its principal ETag. `agent update --http-default` also supports atomic combined direct settings. Policy/default mutations require `--yes`, with one validated preflight for an omitted ETag and no refresh of explicit/stale preconditions. Preview is nonmutating and needs no confirmation. Audit categories/targets `http_grant` (create/update/delete) and `http_default` (update) retain only safe references. Successful policy writes publish coalesced authorization and credential-reference invalidations, never selectors or targets.

## CLI authority, output, and recovery

### Installation and stopped commands

Agent Gateway publishes only `agent-gateway` from one command implementation. Accidental execution of a renamed current binary still exposes canonical grammar/help/completions and the same installation and exclusive process lock; the basename is never disk or credential identity. Publication does not delete or overwrite stale legacy executables. Help uses `agent-gateway`; durable identities and both client export pairs remain unchanged. Repository-owned guest provisioning is retired; manual client configuration preserves both export pairs, with permission and legacy-conflict checks owned by the operator. New launchd installations use `dev.agent-tools.agent-gateway` and canonical logs. Existing custom installations retain explicit-root operation. The migration capability is retired; [selected-root safety and retained historical artifacts](storage-and-recovery.md#installation-selection-after-migration-retirement) remain, with no live relocation or cleanup.

The executable resolves one installation root without mutation: explicit `--data-dir`, otherwise absolute `$XDG_DATA_HOME/agent-gateway`, otherwise the operating-system account home at `~/.local/share/agent-gateway`; relative XDG input fails and `$HOME` is not trusted as an account-home source. Implicit selection does not inspect legacy entries or tombstones; only the selected root's safety checks control access. Explicit selection remains supported; no independent fallback owner, relocation or merge is introduced. `init` (with quiet `initialize` alias) inspects and confirms missing setup, securely prepares that root, publishes a fresh `0600` bearer at `<root>/admin-bearer` before activating initial authority, and creates initial CA material plus `<root>/http-ca.pem`. It preserves established authority and verifies an existing selected bearer without resetting it. Repeated setup can return a read-only no-op while running only when closed-state inspection is safe; changes require stopped ownership. Missing material, unresolved protected-generation evidence and recovery markers never authorize recreation. Public output includes the certificate fingerprint and next serve action. Initialization neither changes services/trust/proxy configuration nor exports private keys. `serve` uses the same existing root and `127.0.0.1:8210`; it never initializes, recovers or resets. Stopped `maintenance reset-admin-credentials` and `maintenance restore-backup` require a fresh explicit `--secret-output`, do not replace the default bearer file, and direct subsequent online recovery to select that new file; `maintenance verify-and-recover-storage` forbids replacement output. Stopped backup restoration uses `maintenance restore-backup BACKUP_ID`; the retired top-level `restore` and `--verify-current` spellings have no execution aliases. Administrator grammar is only `admin credential ...` and `maintenance reset-admin-credentials`; the former hyphenated spellings and `admin reset` have no aliases or compatibility path. Public agent grammar is `agent ...`, without a `principal` alias; API paths, JSON fields, audit identities and durable principal semantics remain unchanged.

`doctor` replaces top-level `status` without an alias. Independent read-only checks distinguish absence, verified facts, failure, presence-only evidence and not-checked capabilities, continuing despite partial failures. Expensive stopped storage validation requires `--verify-storage`; authenticated public status requires `--online`. Public-file presence never proves CA signing ability and doctor never probes protected keyring material. No diagnostic starts services, opens writable storage or performs recovery.

`http ca create` is removed: first creation belongs to init. Stopped `http ca replace` supports verified CA absence, accepts an optional installation-ID assertion, and requires confirmation after inspection. Public output is validated before authority changes and published under the same owner. Export defaults to `<root>/http-ca.pem`, supports explicit file `--output PATH` or PEM-only `--stdout`, and never reads private material. Identical re-export is safe; unrelated files and links are refused. Managed replacement requires previous-certificate identity. Post-cutover publication failure is distinct from unchanged authority and uncertain cutover; recovery is export, never automatic replacement replay.

### Canonical LaunchAgent management

`internal/service` owns installed `service install|start|stop|restart|update|status|uninstall` for only the logged-in non-root macOS user's canonical `dev.agent-tools.agent-gateway` job. No Python, checkout, Go toolchain, shell-wrapped serve, credential access, binary publication, private database opening, migration or recovery is part of management. The canonical private plist is the sole service-settings source. Install selects the current absolute executable and canonical account-home/XDG root unless explicitly overridden, creates private logs and an exclusive plist without loading, and refuses unsafe existing files. Naming migration is the baseline; service management does not import archived plists or inspect legacy identities.

The optional `--http-proxy-listen` selection is disabled by default, validates a distinct numeric IPv4 loopback authority, and is preserved by omitted updates and restart. Explicit `--clear-http-proxy-listen` disables it, mutually exclusive with replacement. No service command creates CA material or client trust.

Update validates the entire proposal before stopping, preserves unspecified installed values and supported diagnostic/output arguments, replaces explicit hostname lists, and offers explicit clearing. An unchanged proposal does not restart. Changed loaded jobs, including loaded-but-exited jobs, retain loaded intent through graceful confirmed stop, atomic private publication, and one bootstrap; unloaded jobs stay unloaded. Restart changes no settings. Start does not restart an already loaded job; stop and uninstall require confirmed job/process absence. Uninstall removes only the canonical plist.

A stable private service-management lock excludes cooperating mutations. Process ownership is scoped to the service/installation, not an executable basename. Exact loaded identity, bounded process observations and existing-lock-only ownership fences fail closed on unknown facts; no Gateway PID is signalled. Existing fences remain held through publication and final job/process/plist revalidation, then release specifically for one bootstrap handoff under the canonical management lock. External foreground/manual launchers must remain disabled during this serialized handoff; the manager does not claim atomic coordination with noncooperating launchers. Utility commands have five-second/1 MiB bounds; their unreaped direct children retain group identity through bounded cleanup. Darwin's zombie-group `EPERM` is accepted only after a fixed one-record group query proves the sole member is that owned, unreaped zombie child (matching PID, parent and group). Missing, partial, multi-member, live or inconsistent evidence remains a cleanup failure; inspection never triggers another signal or utility execution. Tracked service PID inspection includes explicit process state and a validated start-time record. Initial ownership requires the exact executable and a known non-zombie state. After bootout, a same-UID/start-time zombie may retain its exact executable or have an empty, `<defunct>` or parenthesized unavailable-command representation; this permits continued waiting only, never new ownership or confirmed absence. A different executable path, changed UID/start time, unknown state or malformed inspection still refuses. Tracked processes remain blockers until absent, independently of loaded-job, residual-owner and existing-lock fences; displayed start time is coarse and is not a stronger PID-reuse guarantee. Stop observation is bounded to 30 seconds within a 60-second operation context. No uncertain mutation is replayed. Invalid proposals preserve the old service/definition; publication failure retains the old plist, post-stop failure reports stopped/unknown, and a new published definition remains after failed bootstrap without rollback.

Service commands default to terminal-safe human-readable output; explicit `--json` or `--output json` selects machine-readable successes and errors without changing installed serve settings. Mutations summarize the outcome without repeating the configuration, and launch acceptance never implies readiness. Start and restart observe listener readiness for at most ten seconds after their one launch handoff (or an already-loaded start), within the operation deadline. Failure retains launch acceptance, reports unconfirmed readiness and log paths, and directs the operator to `doctor`; it never repeats bootstrap. Read-only service status reports installed selections, launchd state, readiness and log paths separately. Supported definitions with missing standard plist declarations or legacy paired boolean encoding produce an advisory warning (an optional `warnings` array in JSON), not a refusal or automatic rewrite; the hint proves neither native rejection nor acceptance. Unsupported contents still refuse management. Its unauthenticated numeric-loopback readiness request uses the bounded `internal/controlclient` transport without reading a bearer; readiness is not process identity, clean storage or upstream credential health. Unsupported definitions/inspection never become absence. Restart loses process-local authority and in-flight work remains nonreplayable. The [launchd guide](../operators/launchd.md) owns operator procedures and native qualification gaps.

### Online transport and output

MCP permission administration uses only `mcp grant ...` and `mcp grant-request ...`, backed by `/api/v2/mcp/grants`, `/api/v2/mcp/grant-requests`, and `/api/v2/mcp/grant-constraints/validate`. Principals and credentials remain shared top-level administration. Access requests are MCP permission approval, not network traffic. Retired top-level commands and unnamespaced v2 resources have no aliases, redirects, fallback dispatch, or mutation replay; deploy the bundled clients and service together following the [operator cutover](../operators/upgrade-compatibility.md#mcp-permission-namespace-cutover).

`internal/controlclient` is the sole online CLI transport owner. Every online leaf selects administrator authority from an explicit owner-only nonsymlink `--admin-bearer-file`, exclusive `--admin-bearer-stdin`, or the resolved default `<root>/admin-bearer`; simultaneous explicit file/stdin sources fail, and there is no prompt, argv, or environment fallback.

After reading only that credential source, commands use the public HTTP API at a canonical numeric-loopback or explicitly selected hostname destination and never private storage, keyring, lock, or domain owners. Hostname destinations use the same ASCII DNS grammar as allowed hosts and require an HTTP URL with a canonical decimal port from 1–65535, without userinfo, paths, queries, or fragments. Resolution may reach a trusted local forwarding address rather than loopback; this explicit operator trust decision does not provide secure arbitrary-remote administration. Client destination selection is independent of server allowlisting and listener validation. The transport disables proxy, redirect, cookies, compression, keepalive reuse, and automatic retry.

Commands validate bounded closed input before handoff, use command-scoped ETags/idempotency tuples and consequence confirmation, publish one-time bearers or authorization URLs only through a prepared controlling terminal or fresh `0600` owner-only file, and classify pre-handoff versus uncertain post-handoff failures into stable stderr-only problems and typed exit codes. Server create and server credential replacement remain strict-file-only; administrator create, principal create/update, operation start, and request rejection are direct-only; server update, grant create, and request approval accept either direct flags or one mutually exclusive strict file.

Omitted ordinary mutation ETags perform one validated item preflight; explicit ETags skip that convenience read and are never refreshed. Agent issue/rotate always read slot state and respectively require empty/occupied authority. Request approval always reads the submitted policy to reject removal of read-only restrictions or read-only server-to-tool narrowing before mutation; an explicit ETag must match that read and is never refreshed. Backend approval remains authoritative for the full narrowing matrix and concurrent changes.

CLI direct `--read-only` and the browser **Allowed tools** option **Only tools marked read-only** author the existing optional Boolean `read_only` wire member for server ALLOWs only. Strict files retain legacy required members and accept the optional restriction. Grant/request lists and details distinguish unrestricted from read-only authority and retain requested and approved restrictions. Browser **Approve as requested** preserves the submitted selector; customization permits unrestricted server-to-read-only narrowing but locks a requested restriction and server scope. Grant replacement ALLOWs retain read-only authority; replacement DENYs omit the selector and apply server-wide. Contextual UI copy explains explicit `readOnlyHint=true`, future qualifying tools, and that the Gateway does not verify the label or prevent data changes. General help and operator guidance retain the rules for other ALLOW composition and matching DENY precedence.

Human output is the default; `--output json` and `--json` select exact JSON public-API projections. The control client accepts the prior context-free `invalid_server_configuration` envelope during client/Gateway version skew. Finite successes use stdout, finite failures leave stdout empty and use stderr, invalid server configuration failures append the closed field/rule context in human output, startup emits one acknowledgement, clean shutdown emits no stdout trailer, and post-start failure emits one bounded terminal problem. Serve diagnostics are separate JSON lines on stderr, not a change to that problem representation.

No command polls, refreshes a precondition after conflict, recovers a one-time value, invokes a private owner, or replays automatically. A proven refused selected loopback renders the exact `agent-gateway serve` command, including explicit address and data-directory choices. Hostname connection refusal instead directs the operator to check trusted forwarding and the numeric-loopback listener with an explicit allowed hostname; it never recommends a hostname bind.

Command selection, output, authentication-source, and recovery procedures are canonical in [Administrator CLI and local administration](../operators/administration.md).

## Events, limits, and shutdown

### Serve diagnostics

`serve --log-level warn|info|debug` defaults to `warn` (warnings and errors), including actionable upstream unhealthy transitions, foreground OAuth failures/expiration, credential-refresh failures, and observed recovery after a retained unhealthy incident. `info` adds startup, readiness, drain, shutdown, reconciliation displacement, and foreground authorization required/completed; `debug` adds actual reconciliation attempts, retries/resets, OAuth stages/routine refresh success, and the closed invocation and authority/storage stage inventory. Invalid levels fail before startup. There is no text diagnostic format, runtime control API, or verbose mode for other commands. `--output` and `--json` continue selecting results and terminal problems, not diagnostic formatting.

One startup-owned `internal/diagnostics` adapter exclusively imports `log/slog`, encodes JSON and writes stderr. Composition injects narrow invocation, authority, storage, and reconciliation observers; runtime, OAuth, and catalog lifecycle facts reuse the reconciliation observer. Producers pass only fixed typed facts; no logger, arbitrary maps, errors, requests, responses or configuration is injected. Common fields and event-specific subsets are defined by `contract.DiagnosticEvents`. Credentials, tokens, headers, sensitive URLs, tool names, argument keys/values, bearer fingerprints, resource/credential identities, downstream content/errors and subprocess output are prohibited, including at debug. Invalid/unknown/oversized facts are dropped with saturating counters. Standard main HTTP-server raw error logging is suppressed rather than bridged through arbitrary text.

`reconciliation_displaced` is informational: replacing queued/running operation ownership is expected after OAuth reauthorization, not itself a failure. It emits once per captured displaced operation, with optional opaque upstream/attempt references but no resource identity or payload. `reconciliation_settlement_failure` is a warning at the default level because unconfirmed cleanup or unacknowledged terminal persistence blocks further work and needs operator attention. Alongside optional opaque references, its closed cause is `stopped` (cleanup unconfirmed), `capacity` (mutation admission refused), or `unavailable` (other settlement failure). Detailed operation and audit identities remain on authenticated read surfaces. Neither event is authority, confirms durability, nor delays cleanup; both use the same lossy nonblocking adapter.

The upstream inventory has only the closed `phase`, `reason`, and `disposition` vocabularies in `contract.DiagnosticUpstreamPhases`, `DiagnosticUpstreamReasons`, and `DiagnosticUpstreamDispositions`, plus event-specific scalar fields in `DiagnosticEvents`. Connection construction and known dial/TLS failures, MCP initialization, tool discovery (including catalog polls), credential resolution, and foreground/refresh OAuth boundaries are distinct. Unknown facts remain `unknown`; a timeout requires typed timeout evidence, and OAuth expiration requires an observed store expiration. No missing completion is interpreted as a timeout. Each catalog outcome has one observation owner, including explicit OAuth challenge handoffs. A retained Current catalog accompanied by an OAuth challenge is not recovery, and a refresh-eligible challenge alone does not establish operator-auth waiting. `oauth_completed` observes the foreground service's successful return, not active routes or reconciliation success. Recovery is observed only from healthy active catalog publication; it does not certify an operation or durability.

`upstream_ref` and `attempt_ref` are nonzero unsigned 64-bit process counters, not names, hashes, encodings, resource IDs, credential IDs, audit entropy, or arbitrary metadata. The `process_id` scopes their interpretation: 128 independently random bits encoded as 32 lowercase hexadecimal characters, not a clock or PID. Collision resistance is independent of clock rollback and counter restart; this identity uses neither audit entropy nor durable state. If identity entropy is unavailable, `process_id` is empty in stderr and authenticated correlation is omitted; never fall back to clock-derived identity. Composition privately retains at most 1024 resource-to-reference entries (the durable identity cap) for the graph lifetime, including deleted upstreams, so foreground authorization, callbacks, and successive reconciliations share an upstream reference. There is no eviction/reuse within that graph. Atomic allocation never reuses a counter; saturation omits further references. The projection uses a nonblocking lock: contention or capacity can omit correlation without affecting work; an uncorrelated runtime entry can acquire its reference on a later attempt. A new graph releases its predecessor's private projection when that graph is discarded and receives new process-counter allocations. Restart discards all mappings and counters. Authenticated server resources expose an optional `runtime.diagnostic_correlation` object with `process_id` and `upstream_ref` from this same owner. The reference is canonical decimal text in the API to preserve all 64 bits in browser clients; stderr retains its numeric field. Status reads never allocate references. Missing diagnostics, a not-yet-observed upstream, contention or exhausted capacity omit the entire object; deleted resources omit it. The CLI server detail and browser Technical details present both values. There is no unauthenticated or agent lookup authority, reverse-lookup endpoint, second allocator or persistence. Match both fields to a freshly authenticated snapshot, never a reference alone or a cached snapshot from another process. These values are neither durable authority, operation IDs, audit evidence, nor proof of execution.

A reconciliation attempt reference is allocated for each actual worker, carried through displacement and observed completion; the start event is emitted when the goroutine begins, not when queued. A foreground flow gets its own attempt reference retained through callback consumption. `duration_ms` is nonnegative elapsed time capped at 24 hours; zero is omitted. It is not a timeout or deadline. `retry_attempt` is a saturating diagnostic ordinal of scheduled retries, reset with the owner's backoff reset, independently of the public capped retry index. For reconciliation retries, `delay_ms` reports the existing 1/2/4/8/16/32/60-second backoff, capped at 60 seconds indefinitely, never retry exhaustion. The separate debug `catalog_poll_scheduled` event reports the actual delay to the existing five-minute epoch grid (at most five minutes), without a retry ordinal. Failed catalog observations report `retry_scheduled` only after that owner actually installs the next poll; refusal/fencing cannot manufacture a scheduled disposition. Coalesced callers preserve their existing completion timing and do not re-observe the shared outcome: the traversal owner alone reports its actual scheduling result. Diagnostics neither delay waiter completion nor manufacture a second unknown transition from a joined result. Dispositions distinguish execution, retry waiting, operator-auth waiting, verified stopped work, cleanup uncertainty, supersession, cancellation, healthy publication, and unknown next action. Observations add no watchdog, retry, reconciliation, cancellation, or replay work.

`upstream_unhealthy` warns immediately when phase/reason/disposition changes for one upstream. Identical failures are suppressed; the next identical failure at least one minute after the last emitted observation carries the saturating `suppressed` count of intervening observations. Credential-refresh failures have an independent suppression slot per upstream. There is no summary timer or per-event goroutine. The adapter retains at most 2048 suppression slots; capacity evicts the oldest noise history and never suppresses a new owner's first warning. Uncorrelated warnings are not merged. Healthy publication clears both slots and submits one `upstream_recovered` record at `warn` only when the adapter retained unhealthy history, so routine healthy polls are quiet. Successful refresh resets its slot's repeat suppression even below `debug` but retains incident history until healthy publication; foreground OAuth success never clears that history. Recovery always includes `duration_ms` (nonnegative, capped at 24 hours, including zero) from the earliest retained slot's first unhealthy observation to healthy observation, and `suppressed` (including zero), the saturating sum of identical repeats suppressed across both retained slots. Transitions and minute summaries preserve these incident totals; summaries still report only intervening identical repeats. Eviction loses that slot's incident start/count; recovery describes only remaining retained history, or stays silent if none remains. Restart and Finish discard all history. Producer-lock loss is unobserved; queue loss may occur after history changes. Submission, history and counts acknowledge neither sink delivery nor durable commit, and a dropped recovery is not replayed. Foreground operator-initiated flow outcomes are not identical background retries. Suppression state is cleared at `Finish`; all diagnostic state remains bounded and independent of lifecycle authority. Loss can hide either a transition or its recovery.

Every warning/error record includes a closed `action` from `contract.DiagnosticActions`, computed only from validated typed facts. Cleanup uncertainty takes precedence (`inspect_settlement_no_replay`); actual scheduled work selects `wait_scheduled_retry` rather than an operator replay. Operator-auth waiting selects `authorize_upstream`; typed credential, connection and configuration reasons select `inspect_credentials`, `inspect_connection` and `inspect_configuration`. Unknown facts and lifecycle failures select `inspect_status`. Storage latch/durability failures select `storage_recovery`, loss selects `inspect_diagnostic_sink`, and recovery selects `no_action`. These are troubleshooting classifications, not runtime commands or new authority. None recommends replay of uncertain execution; operator procedures define safe inspection and separately authorized recovery.

The queue holds at most 256 records: 255 ordinary fact records plus one reserved terminal-problem record. Ordinary submissions drop newest without waiting, including producer-lock contention. Facts contain only bounded metadata; only the worker encodes, with at most 4 KiB per encoded record including newline. Encoded queued data cannot exceed 1 MiB; the one worker has one bounded in-flight record. There are no per-event goroutines or replacement writers. Loss summaries aggregate dropped and invalid counts at most once per second when delivery is possible; their failures do not recursively count themselves.

After durable/runtime cleanup, shutdown stops ordinary submissions and allows at most one second total for accepted records and the existing single-owner terminal problem. All complete records and the problem share the same writer, preserving byte boundaries and problem format without an unbounded post-start stderr write. An arbitrary blocked OS Write can remain owned until process exit: cancellation cannot interrupt every pipe or terminal. Never close inherited stderr, restart a writer while one remains outstanding, or claim a flush acknowledgment on timeout. In-process fixtures must release only their owned sink and join the adapter's actual `Done` signal before replacement. Broken/short writes disable further output without replay; an incomplete final line and undelivered records are possible. Diagnostic loss alone changes neither service exit nor settled storage cleanliness; actual cleanup uncertainty retains its existing behavior. Logs are not audit evidence or permission to replay.

### Event delivery

The authenticated event hub admits 16 streams with 16 buffered invalidations each. Publication is nonblocking and carries only the closed safe `admin_credentials`, `system_status`, `backups`, `servers`, `server_operations`, `server_auth_flows`, `catalog`, `authorization`, `invocations`, `grant_requests`, and `http_credentials` representations; production emits every listed kind, invocation admission and terminal commits publish refresh hints that may be coalesced without IDs, and approval publishes `grant_requests` before `authorization`. Frames have no ID, cursor, replay, or storage authority. Connect and reconnect begin with no history; a full buffer disconnects the slow stream so its client recovers by reloading authenticated snapshots. A 15-second comment keepalive and per-write deadline bound dead peers. Request cancellation, session terminal state, parent-bearer invalidation, and shutdown close the stream and release its permit.

Traffic `invocations` and `system_status` hints are coalesced server-side over
250 ms before delivery, without resource IDs or replay. New subscribers do not
receive pre-subscription hints. One timer per hub is joined at shutdown; bounded
buffers still disconnect slow readers. Other event ordering is unchanged.

### Occupancy and status

System separates control readiness/latch from traffic readiness, persistence
faults, pressure, combined DB/WAL bytes, quota refusals and pruning. It explains
rolling history and unknown completions without treating status as execution
proof. Traffic-only failure leaves healthy operator inspection and revocation
available; only the control latch globally closes administrative mutations.
The optional typed status addition is defined in the [public contract](public-contract.md#independent-traffic-status).
`serve` and canonical service install/update persist the validated 4 GiB default
traffic budget, preserving omitted installed selections. Snapshot, migration and
backup staging consume separately bounded disk allowance.

Event streams release authenticated-admin admission after authentication because their own registry supplies the lifetime bound; saturation therefore cannot consume the status/recovery pool. Live status composes the independent HTTP, session, MCP, event, backup, keyring-work, candidate, credential, idempotency, backup-record, database, durable server identity, nondeleted server, process-local runtime, reconciliation, foreground OAuth-flow, principal, grant, global request-row, and request-evidence-byte occupancies from their actual owners. Principal/grant reads come from the sole composition-owned authority and retain fixed zero-use limits on a transient read failure; `agent_auth` is `principal_credentials`, sourced from the same composition bundle as the positive authenticator and discovery service. Server reads compose process-local runtime state and safe reason/runtime identifiers over durable desired authority; restore never turns durable rows into active facts before fresh reconstruction. Every admission and retained-record cap is compiled, rejects before expensive allocation without queuing, and releases on every terminal path.

### Drain and shutdown

The first `SIGINT` or `SIGTERM` atomically enters drain, makes readiness false, and invokes the composition's one-shot drain before storage closure. Its synchronous prefix first fences new invocation pipelines, then fences authentication, removes and cancels every registered pre-admission lease, marks the active catalog draining so old discovery generations are non-current, and withdraws active routes. It then cancels catalog work, fences OAuth and keyring producers, snapshots every runtime-owner phase, launches independent stops concurrently, and waits outside authority/catalog locks for invocation pipelines through terminal annotation plus authority-gate and owner quiescence within the fixed ten-second bound while events, MCP compatibility state, admin sessions, and HTTP are closed. A second signal invokes immediate forced exit rather than waiting for context-free work. Graceful completion removes the durable run marker only when every owned runtime stop is verified; forced, expired, or blocked cleanup leaves it for the next startup's full storage verification. Runtime registries are never serialized, so no session or in-flight work resumes.
