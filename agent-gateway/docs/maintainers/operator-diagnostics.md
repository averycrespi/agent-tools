# Operator diagnostic coverage

Audience: Gateway maintainers and reviewers

Purpose: Trace original failures to their single local observation owner and keep
public projection separate. This is a source/test map, not an execution report or
qualification of installed services. Native-manager utility diagnostics are retired; operator-owned launchd/systemd inspection is outside this source matrix. Remaining schema-2 local detail, public classifications and CLI output contracts are unchanged.

The [disclosure policy](../design/administrative-control-plane.md#operator-diagnostic-disclosure-policy)
is normative. [Operator guidance](../operators/administration.md#safe-serve-diagnostics)
owns private captures and interpretation.

Traffic-loss summaries use `operator_failure` records with `operation=capture loss
summary`. The adapter's existing one-second ticker and final drain emit at most
one changed cumulative record per fixed reason per cycle; there is no per-request
warning, additional timer, writer, durable counter or retrospective history repair.
Failed sink delivery remains unconfirmed even when a counter or record was accepted.

## Reviewing the disclosure boundary

- Pair positive assertions (native reason, affected path/authority, known effects)
  with genuine credential fixtures. A hostname, server ID or benign injected error
  is not itself a secret canary.
- Follow causes from their source, not only from `Adapter.Observe`. Local wrappers
  deliberately preserve public `Error` and classification; rich detail must never
  be copied into API problems, audit/history, events or backup representations.
- `Detail` contains strings only. Snapshot outside owner locks; no arbitrary error,
  request, material lease or callback is put on the logging queue. Masking inputs
  are bounded to 128 values/64 KiB; excessive masking material yields an explicit
  withheld-detail explanation. If inherited detail was truncated before new source masking material became available, that field is withheld because full-value replacement cannot establish prefix safety. Error topology is bounded to 16 nodes. Cyclic or
  excessive graphs produce a visible traversal fallback.
- Source-owned secret values are masked before truncation. Known credential/header
  labels, private-key blocks and URL userinfo/query/fragment receive additional
  filtering; these patterns do not replace source-aware masking. Child/library
  excerpts are labeled untrusted and terminal controls escaped.
- Unknown or transformed third-party secrets cannot be universally recognized.
  Trusted Go error implementations must themselves return promptly; the envelope
  cannot safely preempt arbitrary `Error` methods. Do not claim logs are safe for
  unrestricted sharing, or treat source fixtures as native/live qualification.
- Identical repeats, producer/queue loss and sink-write uncertainty are different
  facts. A queued record or suppressed-repeat count acknowledges no delivery,
  durable commit, rollback or safe replay. Retain the existing one-second flush,
  sole writer and blocked-fixture release/join rules.
