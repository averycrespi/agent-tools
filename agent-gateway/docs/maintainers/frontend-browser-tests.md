# Mocked frontend browser tests

## Choose the evidence owner

Use `make test-frontend-browser` (or `npm run ui:test-browser` at the repository root) for frontend rendering, forms, navigation, accessible states, revision-conflict presentation and the screenshot gallery. It runs the committed production bundle in pinned Chromium, serves only static assets and a synthetic invalidation stream, and intercepts control APIs with deterministic fixtures. It does not start Gateway, initialize storage, access keyring, or use installed services or real credentials.

Use `make -C agent-gateway test-browser-workflows` and the other real-Gateway browser leaves for authenticated API behavior, cookies/Origin, actual persistence, proxy correlation, process lifecycle and credential authority. A mocked response cannot qualify any of those boundaries. Node contract/foundation tests remain the fast owner for exhaustive decoder and coordination cases. Run `npm run ui:build` after source changes; use `npm run ui:verify-generated` to check the committed bundle.

```bash
npm ci
npx playwright install --with-deps chromium --only-shell
npm run ui:test-browser
# Focused work; the report explicitly lists unselected owners:
npm run ui:test-browser -- --grep 'http-credentials'
```

There are no pixel baselines, screenshot comparisons, snapshot updates or automatic visual approval. Optional legacy baseline hooks do not run for frontend-owned pages. Playwright uses two bounded workers; every test owns a new context, closed API fixture and ephemeral loopback listener. The frontend fixture rejects axe injection so shared scenarios cannot silently reintroduce automated scans; those scenarios retain their original scans outside frontend-owned execution. No Gateway fixture or port handoff is shared with this suite.

## Capture and inventory contract

`web/tests/frontend/inventory.json` is the checked expected checkpoint inventory, not a file regenerated during test execution. Its owner IDs match test names. Every standard checkpoint requires desktop (1440×900) and mobile (390×844), each in light and dark themes. Reflow checkpoints additionally require 320×844 and 640×450. The latter is the CSS-viewport equivalent used for targeted 200% reflow, not a claim about browser zoom APIs. Every combination checks horizontal overflow. Explicit role/name, keyboard/focus, labels, layout and behavioral assertions remain in the scenarios, but this suite deliberately does **not** run automated axe scans. This runtime tradeoff removes systematic automatic detection of contrast, label, ARIA and structural accessibility defects; neither a passing suite nor its gallery establishes full accessibility conformance. Pre-existing independent real-Gateway accessibility owners retain their scans and coverage.

`capture.ts` captures explicitly asserted, settled checkpoints, including held pending responses; it does not infer state from elapsed time or a mutation observer. It restores viewport, theme preference, exact local-storage presence, focus and scroll position. Native required validation is asserted through validity and the app-owned form is captured; Chromium's transient native validation bubble and native leave prompts are not themeable application dialogs.

Each execution has a fresh UUID under `.frontend-browser/runs/`. Only that run's images and metadata can satisfy its inventory. `.frontend-browser/index.html` links to the latest run. Each run contains an HTML gallery, `inventory.json`, organized `captures/<owner>/<state>/<theme>-<viewport>.png` images and metadata, and failure context. Missing, unlisted, invalid or unknown-owner artifacts fail qualification even when behavioral tests pass. Focused runs qualify only selected owners and explicitly enumerate `notSelected`; they are not full-suite evidence. Failure reports preserve completed and partial evidence. Prior runs remain separate and cannot cover missing current captures.

Pages use full-page captures. Scrollable native dialogs additionally produce bounded, overlapping `-dialog-2.png` continuations through the bottom; metadata lists these supplementary images and qualification checks their PNG files. The gallery labels continuations under the same state/theme/viewport rather than treating them as different application states. Operation polling assertions advance a controlled browser clock from a fresh visible interval, so screenshot duration cannot silently add timer ticks.

Open the gallery and inspect full-size images deliberately for clipping, overlap, wrapping, hierarchy, dialogs, below-fold content and readable light/dark contrast. Screenshot production, dimensions, hashes and DOM assertions are not visual inspection. All data, bearer strings, one-time values and authorization URLs are synthetic. Do not substitute production credentials or upload live-service captures.

## Source-derived surface map

The route grammar is `web/src/location.ts`; the shell and global overlays are in `main.tsx`, `navigation.tsx`, `sinks-ui.tsx` and `toast.tsx`. Owner/state keys below resolve to the checked capture inventory. When adding a page, dialog, disclosure, form branch or failure state, update its scenario **and** inventory in the same change; adding only a happy-path route screenshot is insufficient.

The Node inventory guard fingerprints the router, rendered TSX owners and styles, and checks their exact file inventory. Any new or changed surface therefore requires an explicit coverage review, even if no test was added. After reviewing its affected states and updating scenarios/mapping, update that file's SHA-256 in `sourceDigests` (for example, `shasum -a 256 agent-gateway/web/src/main.tsx`), then run the Node guard and affected browser owners. Fingerprints are change-detection prompts, not proof of semantic coverage or visual baselines; never update them to suppress an unexplained failure.

### Applicable-state exceptions

- Read-only collections/details have no write-confirmation, mutation conflict, pending write or uncertain-write state. Recorded unknown outcomes in history are separate evidence, not a replayable mutation.
- Forms have no collection-empty state. Create forms without a prerequisite read have no independent initial loading state. Choice-loading/empty/error belongs to forms that actually fetch choices.
- A static confirmation has no independent collection/loading/validation/error lifecycle: submission closes it and the owner displays pending/rejected/conflict/uncertain state. Typed namespace deletion and input-bearing rejection dialogs are exceptions and retain their validation variants.
- Git traffic uses authoritative recorded-history filters and bounded live/older browsing without column sorts. Git resource inventories use authoritative filters/sorts; the resource owners cover query forwarding, Reset and detail return. `git-inventory-routing` covers paging and shared routing guidance: missing/exact-origin coverage, inactive, loading, unknown, stale, and nonblocking create review. Git missing detail uses the generic read-error surface, not an invented pruned-history screen. Resource-limit tables have no editable or dedicated empty state.
- Successfully loaded audit related events always include the selected event; an empty related response does not make an independently reachable empty panel.
- Mobile navigation-open has no desktop overlay counterpart; the desktop equivalent is the navigation rail. Browser-native leave/validation UI has no app light/dark variant.
- No backup detail/restore route, administrator credential detail/edit route, server operation cancellation dialog, tool invocation modal or stored-secret reveal exists. Closed router fallback branches and the unreachable second request rejection confirmation are not separate workflows.
- One-time bearer/URL dialogs have awaiting/display/lost and clipboard/popup variants, not editable validation or stale-resource revision conflicts. HTTP access preview is read-only despite using POST and has no uncertain-write/replay lifecycle.

## Ownership migration and CI

The former Go wrappers for mocked Agents/credentials, MCP grants/requests, Overview/invocation presentation/System/backup/admin presentation, server catalog/operations/auth flows/credential replacement/disconnect-delete were removed. Their domain scenarios execute through the frontend fixture instead. HTTP traffic and audit retain separate real API sections and move intercepted presentation into this suite. The existing server-create/update real owner now retains only real upstream-header create/update/persistence evidence; intercepted editor workflows execute here. Invocation-history, authenticated administration/proxy tests, restart/lifetime, real-Gateway canaries and distinct privacy/accessibility/visual integration evidence remain real-Gateway owners.

The independent **Frontend browser** GitHub Actions job runs in parallel with selected Gateway checks and is required by the stable **Required** gate. It uploads the gallery, inventory and partial failure captures on success or failure, retains them for 14 days, and links the artifact from its job summary. An upload or setup failure is reported separately from browser qualification. Local screenshots are ignored by Git; do not commit generated galleries.
